# Audit: the verification gates (2026-10-03)

**Scope.** The gate infrastructure itself, not any one gate's oracle: `scripts/check.mjs` (lanes,
modes, pass/fail and reporting), `.github/workflows/ci.yml`, `ci/scripts/*`, `.config/nextest.toml`,
the node gate scripts in `scripts/` (`lists-in-step`, `clippy-denylist`, `claude-md-budget`,
`privacy-canary`, `size-gate`, `mobile-check`, `physics-features`, `import-sync`, `ludion-bin` and the
four drift gates), the `ludion-cli` embedded-docs build check, the schema snapshot test, the bless
switches the tests read, and the `budgets/` files with the `check_budget` path that reads them.
Working tree read at mirror rev `b1c847c3` (Lore is ahead; uncommitted gate edits were read as they
stand). Private CI configs are out of scope; parity with them is noted only in general terms.
Already reported elsewhere and not repeated: the weaker inline denylist canary (ecs-par E1), the
luma-only and tile-window golden comparison (render-graph G1/G2), drift gates that enumerate outputs
(fonts-ui F7, mesh-edit-sculpt M2), and the audio test gaps (U1/U2). Two read-only scripts were run
(`lists-in-step.mjs`, `claude-md-budget.mjs`, both green) plus `cargo fmt --check` on `fuzz/`.

## Overall assessment

The gates are well built. `check.mjs` and `ci.yml` run the same commands step for step; no exit
code is swallowed; nothing pipes, `|| true`s or `continue-on-error`s a failure away; and
`lists-in-step.mjs` turns three hand-kept lists into checked ones. The holes are in what a green run
*means*. The worst one: on the pinned-GPU lanes, where alone the image and timing gates run, a
missing adapter turns every golden, GPU test and `[passes]` budget line into a quiet pass, and no
test checks that the adapter is there. Next, the hosted CI excludes whole test binaries rather than
GPU tests, so CPU-only drift gates that other gates hand off to never run there. Three CI jobs skip
the derived-import sync their tests need. A `--full` run edits tracked source in a checkout that
other instances share. The bless switches do not all agree on what "set" means.

## High

### Q1 — On a pinned-GPU lane, a missing adapter makes every golden and GPU test pass silently · High · [verified]

**Evidence.** `GoldenTest::single` turns `L2003` into
`eprintln!("SKIPPED golden test: no GPU adapter (L2003)")` and returns
(`crates/ludion-testkit/src/golden.rs:307-309`). Every CLI render suite hand-rolls the same skip
(`crates/ludion-cli/tests/render.rs:45-47`, `import.rs:394-398`, and the rest of the `gpu` list).
nextest prints a passing test's stderr only on failure (`final-status-level = "slow"`,
`.config/nextest.toml:27-28`). `check.mjs`'s summary picks out slow tests only
(`scripts/check.mjs:633-640`). No environment switch, test or step checks that the box which is
supposed to gate images actually has its adapter. The only adapter check is the bless-side `L2206`
(`golden.rs:452-484`).

**Why it matters.** Pillar 3's image tier runs only on the two pinned machines and their private CI
agents: hosted CI leaves these binaries out by design. Those lanes have no second line of defence.

**Failure scenario.** A driver update in progress, a CI agent running as a service with no GPU
session, or a box with its discrete card disabled. `request_adapter` returns nothing, about 40 golden
and render binaries print `SKIPPED` into output nobody reads, and `ALL GREEN` is reported over a
real colour or geometry regression.

**Fix.** Add a `LUDION_REQUIRE_GPU=1` contract: the testkit's skip helper and a shared
`is_no_adapter` panic when it is set. Set it in `check.mjs`'s default-profile `test` step and on
every private GPU agent. Leave it unset under `--profile no-gpu`. Optionally, have `check.mjs` count
`SKIPPED golden` lines in `test.log` and fail on any.

## Medium

### Q2 — A budget check reports "all timings within budget" when no GPU pass was measured · Medium · [verified]

**Evidence.** `profile_gpu` returns `available: false, passes: []` on `L2003` without an error
(`crates/ludion-engine/src/profile.rs:635-652`). `check_budget` skips a producible `[passes]` key
that is missing from the report (`profile.rs:1048-1051`), and a pass with `median_ms: None` (no
timestamp support) (`profile.rs:1037`). `[post_groups]` and `post_total_ms` skip when no member was
measured. `check_budget_report` then prints `all timings within budget` and exits 0
(`crates/ludion/src/lib.rs:1276-1279`).

**Why it matters.** The skip rule is right for one scene that never schedules a pass. It is wrong for
a whole run where nothing on the GPU was measured. The budget configs run on the pinned machines and
nowhere else.

**Failure scenario.** The same adapter loss as Q1, or a backend without timestamp queries, during the
budget run. Every `[passes]` and `[post_groups]` ceiling in `budgets/pinned-*.toml` passes without
being compared, and only `frame_total_ms` and the CPU lines are really checked.

**Fix.** In `check_budget`, return an error diagnostic (a new code) when the budget names any
`[passes]`, `[post_groups]` or `post_total_ms` line and `report.gpu.available` is false, or when
`timestamps_supported` is false. Keep the per-key skip for the scene-shaped case.

### Q3 — Hosted CI excludes whole binaries, so about 360 tests, CPU-only drift gates among them, run in no hosted lane · Medium · [verified]

**Evidence.** The `no-gpu` profile excludes 40 binaries by `binary_id`
(`.config/nextest.toml:193-237`). `ci.yml:113` runs that profile in the `check` job. The excluded
binaries contain about 360 `#[test]`s, many of them CPU-only.
`crates/ludion-cli/tests/import.rs` holds `textured_import_reproduces_committed_tree_in_default_mode`
(`:127`), the gallery skin-mesh drift test (`:315`) and the clip drift test
`the_committed_gallery_mannequin_clips_match_a_fresh_import` (`:348`). None of these renders. They
are also the gates that `map-drift.mjs` hands imported `*.anim.yaml` and `*.prefab.yaml` off to
(`scripts/map-drift.mjs:52-58`). `ludion-cli::render`, `serve`, `test_cmd`, the `ludion-server`
integration suites and `ludion-engine::model_sheet` (55 tests) carry many more CPU-only error-path
tests.

**Why it matters.** `ci.yml` is the canonical gate set. Each excluded CPU test runs only on a pinned
GPU box, and one hand-off between gates (map-drift to import.rs) goes vacuous on every hosted run.

**Failure scenario.** An importer change alters the bytes of a committed clip under
`examples/gallery/clips/`. Hosted CI and the GPU-less private agents are green. The drift shows up
only when someone next runs `check.mjs` on a pinned machine.

**Fix.** Exclude by *test*, not by binary. Either split the CPU-only tests of the mixed binaries into
their own `tests/*.rs` files (cheapest for `import.rs`: move the drift tests into `import_drift.rs`),
or mark GPU tests with a name prefix and filter on `test(/^gpu_/)`. Extend `lists-in-step.mjs` so
that a no-gpu-excluded binary with tests that have no GPU marker is flagged.

### Q4 — CI's `thread-identity`, `probe` and `soak` jobs never sync the derived-import tree that vigil's scenes reference · Medium · [verified gap; consequence suspected]

**Evidence.** The `check` job runs `node scripts/import-sync.mjs` before nextest (`ci.yml:107-108`),
and `check.mjs` orders `import-sync` before `test` (`scripts/check.mjs:404-410, 446`). The three
`#[ignore]`d-campaign jobs check out fresh and go straight to nextest (`ci.yml:263-293, 295-322,
324-351`). vigil's `[[import]]` writes the git-ignored `games/vigil/assets/town`, and committed
scenes point into it: `games/vigil/scenes/district-breach.yaml:940` and the
`scenes/prefabs/town/*.prefab.yaml` set. The probe campaign routes through breach
(`games/vigil/tests/probe.rs:1772`). Locally, `check.mjs --full`/`--soak` always run the default
lanes, sync included, first. So only CI hits the gap.

**Why it matters.** These are the determinism campaigns. Depending on how a missing derived mesh is
handled on the path each job takes, the job either fails for an environmental reason or checks hash
identity of a world that is missing its mesh colliders and props. Both runs lack the same assets, so
identity still holds and the job reports green.

**Failure scenario.** A change to a town kit's collider mesh breaks thread-count identity only when
that mesh is present. CI's `thread-identity` job never loads it and stays green.

**Fix.** Add the `derived imports sync` step to all three jobs, and to any future job that runs
vigil. Better, make the sync a precondition that vigil's test harness checks: fail with
`run ludion sync` when `assets/town` is absent, as `games/vigil/tests/spectacle.rs:435` already does.

### Q5 — `check.mjs --full` edits tracked source in the shared checkout for minutes, and a kill or a parallel run leaves it changed · Medium · [verified by reading; not reproduced]

**Evidence.** The canary appends two functions to `crates/ludion-core/src/lib.rs`, runs a full
`cargo clippy -p ludion-core`, then restores from a backup (`ci/scripts/denylist-canary.ps1:15,
57-60`; `.sh` uses `mktemp` plus `trap ... EXIT`). `check.mjs` runs it in the shared checkout
(`scripts/check.mjs:300-302, 700`). The PowerShell backup path is fixed
(`ludion-denylist-canary-lib.rs.bak` in `%TEMP%`), so two runs on one machine share it.
`ci/scripts/schema-drift.ps1:20` has the same pattern. The default-mode `schemaDrift` overwrites
`editor/protocol/src/protocol.d.ts` and restores it afterwards (`check.mjs:502-505`). Every run also
starts by `rmSync(.build)`, which deletes the binaries a concurrent run copied there
(`check.mjs:673`, `416-423`).

**Why it matters.** Several instances edit this checkout at once. While the canary is in place:
(a) another instance's build or clippy of anything that depends on `ludion-core` fails on the
canary, which reads as a real defect to fix; (b) any edit another instance makes to that `lib.rs`
(or to `protocol.d.ts`) is silently reverted at restore; (c) a `--full` run killed by PID (the usual
way a background lane is stopped) skips the PowerShell `finally`, so the canary stays in the tree
where a path-scoped commit can pick it up; (d) two overlapping PowerShell canaries back up each
other's canaried file, and the second restore fails because the first one deleted the shared
backup. The canary is left in place.

**Failure scenario.** Instance A starts `check.mjs --full`. Instance B adds a re-export to
`ludion-core/src/lib.rs` and runs `cargo test -p ludion-core`, which fails on `_libm_canary`. Two
minutes later A's restore erases B's re-export.

**Fix.** Run the canary on a copy: a scratch crate, or `CARGO_TARGET_DIR` plus a temporary
`[patch]`, or a crate generated under `target/` that path-depends on `ludion-core` and inherits its
`clippy.toml`. Then the checkout is never written. Give `schema-drift` an output path flag so the
generator writes to a temp file. Use a unique backup name (`New-TemporaryFile`) in both `.ps1`
scripts. Take a lockfile under `target/` for the length of a `check.mjs` run and report a second run
as "busy" instead of deleting `.build/`.

### Q6 — The bless switches disagree on what "set" means, and check.mjs's guard covers only one of them · Medium · [verified]

**Evidence.** `check.mjs` refuses to start only when `LUDION_BLESS` is non-empty and not `0`
(`scripts/check.mjs:87-95`), which is the testkit's own rule (`golden.rs:517-519`). Five
committed-trace tests bless on `var_os("LUDION_BLESS").is_some()` instead, so `LUDION_BLESS=0` and
`LUDION_BLESS=` both bless: `crates/ludion-core/tests/trs_bits.rs:113`,
`crates/ludion-engine/tests/physics_gallery.rs:71`, `crates/ludion-engine/tests/physics_stress.rs:117`
(the same file defines the correct `bless_requested()` at `:63-65` and does not use it here),
`crates/ludion-physics/tests/layers.rs:735` and `crates/ludion-physics/tests/pile.rs:262`. Each one
rewrites its committed cross-arch trace and returns green. `BLESS_SCHEMA` is not refused at all. Any
value rewrites `tests/protocol_schema.snapshot.json` and returns before both assertions, the
`EXPECTED_SCHEMA_HASH` one included (`crates/ludion-protocol/tests/schema_snapshot.rs:29-36`).

**Why it matters.** These traces are the bit-exact cross-arch determinism fixtures. A run that
re-blesses them passes on a determinism regression and leaves the regressed fixture in the tree to be
committed.

**Failure scenario.** A shell has `LUDION_BLESS=0` set, read as "off". `check.mjs` starts, and the
`physics_step` change under test, which shifts the pile's trace, is written into
`examples/gallery/physics-pile.trace.txt` with the run reported green.

**Fix.** Route every bless check through one helper (`ludion_testkit::bless_requested` or a copy with
the same semantics) and add a `lists-in-step`-style grep that fails on `var_os("LUDION_BLESS")`. Have
`check.mjs` refuse `BLESS_SCHEMA` too. In the schema test, still assert the hash constant after a
bless, so a bless without updating it fails in the same run.

## Low

### Q7 — `lists-in-step` only scans integration-test binaries, and only validates the GPU lists · Low · [verified]

**Evidence.** `scanWorkspace` collects only `tests/*.rs` binaries (`scripts/lists-in-step.mjs:56-77`).
The `ludion-engine` lib's unit tests call `profile_engine`, which builds a renderer through
`engine.renderer()` (`crates/ludion-engine/src/profile.rs:635-652`, tests from `:1487`). That lib
binary is in neither list, while `ludion-renderer`'s lib had to be added by hand. Entries in the
`wall-clock`, `cargo-build` and priority overrides are never checked for existence (`elsewhere`,
`:116`, is used only for membership). Renaming `call_timeout.rs` or `e6_bench.rs` would quietly drop
its serialization and bring back the P0 timing flake the group exists to stop.

**Fix.** Scan `src/` `#[cfg(test)]` modules for the same GPU markers, keyed by the lib's binary id,
and check that every `binary_id(=...)` in every override exists.

### Q8 — The shipped (no-`wire`) feature shape is linted but never tested · Low · [verified]

**Evidence.** `mobile-check.mjs` runs `clippy ... --lib --no-default-features` for the facade and for
vigil (`scripts/mobile-check.mjs:44-61`): no `--all-targets`, no `cargo test`. The facade's embed and
FFI tests (`crates/ludion/src/ffi.rs:553`, `embed.rs:878`) therefore compile and run only with
`wire`+`window`, so the `#[cfg(not(feature = "wire"))]` paths of `start`/`try_start`
(`ffi.rs:179-182, 258`) run in no test. The iOS-target lint skips on every hosted runner, because
`rust-toolchain.toml` installs no `aarch64-apple-ios` target (`mobile-check.mjs:65-77`).

**Fix.** Add `cargo test -p ludion --no-default-features --lib` (and `--features wire`) to
`mobile-check.mjs`. If the iOS lint should gate on macOS CI, add the target to the macOS job.

### Q9 — `ci.yml` has never run, and its `check` job leaves Node unpinned while using a Node ≥21 feature · Low · [suspected]

**Evidence.** The mirror has no remote yet, so the workflow has never executed. The `check` job is
the only job running Node gates without `actions/setup-node` (setup is at `ci.yml:408, 439` only).
`node --test "games/vigil/art/town/lib/*.test.mjs"` (`ci.yml:184`, quoted) and the unquoted
`scripts/voxel/*.test.mjs` (`:179`, unexpanded under Windows' default pwsh) depend on the test
runner's own glob support, which arrived in Node 21. The other scripts state "node 22+".

**Fix.** Add `actions/setup-node@v4` with `node-version: "22"` to `check`, `packaging` and the
campaign jobs. Treat the first published run as a gate bring-up: expect latent defects like this one
and Q4.

### Q10 — No timeouts anywhere in the lane · Low · [verified config; consequence suspected]

**Evidence.** `.config/nextest.toml:25-28` deliberately sets no `terminate-after`. `ci.yml` has no
`timeout-minutes`, so GitHub's 6-hour default applies. `runStep` has no timer
(`scripts/check.mjs:139-163`). A test stuck on an unkillable shutdown (wire-server W2) holds the lane
until someone notices.

**Fix.** Set `slow-timeout = { period = "60s", terminate-after = 10 }` (a 10-minute ceiling, well
above the longest replay) and give each CI job `timeout-minutes`.

### Q11 — `fuzz/` is compile-checked only: no fmt, no clippy · Low · [verified]

**Evidence.** `fuzz/` is a detached workspace (`fuzz/Cargo.toml:15-16`), so `cargo fmt --all` and
`cargo clippy --workspace` at the root never reach it. The only gate is
`cargo check --manifest-path fuzz/Cargo.toml` (`check.mjs:294`, `ci.yml:220`). The tree is
fmt-clean today (checked).

**Fix.** Add `cargo fmt --manifest-path fuzz/Cargo.toml --all -- --check` and a clippy step next to
`fuzz-check`.

### Q12 — Three gates exist in three copies, and the "generic gate scripts" are not what `ci.yml` runs · Low · [verified]

**Evidence.** Schema-drift: `ci/scripts/schema-drift.{sh,ps1}`, the inline `ci.yml:389-424` job, and
`check.mjs:499-514`. Shader-drift: `ci/scripts/shader-drift.*`, `ci.yml:138-139` and
`check.mjs:519-530`. Denylist: `ci/scripts/denylist-canary.*`, `ci.yml:353-387` and `check.mjs`
(which calls the script). The script headers say `ci.yml` mirrors them, but `ci.yml` never invokes
them. Inlining is how ecs-par E1's weaker canary happened. The nextest-less fallback has drifted the
same way: `ignoredStep` scopes `thread-identity` to `-p vigil -p breakout`
(`check.mjs:383-388, 704`) and so misses `crates/ludion-engine/tests/thread_identity.rs` (7 ignored
tests), which the nextest form `binary(thread_identity)` includes.

**Fix.** Have `ci.yml` call `ci/scripts/*.sh` with `shell: bash` on both OSes, and the same in
`check.mjs`. Derive the fallback's package list from the workspace (or drop the fallback for
`--full`).

**Evidence.** `dev-docs/budget-files.md` does not list `budgets/pinned-*-gi-inject-stress.toml` at
all, and says the sprite-stress and physics-stress files have no M4 twin (`:38-40`, `:51-56`). Both

### Q14 — Nothing outside the pinned budget runs parses the committed budget files · Low · [verified]

**Evidence.** No test loads `budgets/*.toml` or `games/vigil/budgets/*.toml` (grep for `budgets/` in
`crates/` and `games/` finds only comments). `load_budget`'s `deny_unknown_fields` and the static
`[passes]`/`[post_groups]` name check (`L4006`) need no GPU, but they run only when a pinned machine
runs `profile --check`. For vigil's E6 files that never happens, as `dev-docs/budget-files.md`
records.

**Fix.** Add a CPU test that loads every committed budget file and checks its `[passes]` and
`[post_groups]` keys against `KNOWN_PASS_NAMES`/`POST_GROUPS`. A pass rename then fails per push,
not at the next sitting.

## Checked and healthy

- **Exit codes.** `runStep` fails on any non-zero or null code. Spawn errors fail. Skipped steps never
  hide a failed predecessor: the predecessor's own red stays in the summary. The node gate scripts
  all `process.exit(1)` on their error paths. `ci/scripts/*.sh` use explicit `if !`/`exit 1`, and
  the `.ps1` scripts check `$LASTEXITCODE`. No `|| true`, `continue-on-error` or exit-masking pipe in
  `ci.yml`.
- **Parity.** Every `check.mjs` default/`--full`/`--soak` step has a `ci.yml` twin with identical
  flags (fmt, clippy `--all-features`, nextest + doctest, check-docs, mobile, the five node test
  suites, the four drift gates, Tauri fmt/clippy/test, fuzz check, package with the purge, doc
  `-D warnings`, thread-identity, probe, soak, schema-drift, oxlint/tsc/vitest). `deps-guard.sh` is
  absent from both on purpose and says why. The profile difference (`default` locally, `no-gpu`
  hosted) is deliberate.
- **`lists-in-step`** runs green. It keeps the `gpu` and `no-gpu` lists in step, checks binary
  existence and the fps override's regex, compares `ludion.h` with `ffi.rs`, and checks the generated
  `clippy.toml` files, all in every mode.
- **Embedded-docs mirror.** `crates/ludion-cli/build.rs` panics on any changed, missing or extra
  topic. `--fix`'s re-mirror only deletes `.md` files that have no `docs/` source.
- **Drift-gate plumbing.** `ludion-bin.mjs`'s fallback quotes arguments. Each gate fails on a missing
  named source, and map-drift's `.rs` hand-off checks that the named test mentions the scene.
- **Privacy and size gates** share one public-file set (`ls-files -co` minus `check-ignore --no-index`).
  The canary's skip on a public clone is printed and documented.
- **`.gitattributes`** forces LF with explicit binary types, so byte-compared fixtures survive a
  Windows checkout. `git ls-files --eol` shows no CRLF or mixed text files.
- **Feature unification.** `ludion-font`'s `bake`-gated tests run under `--workspace`, because
  `ludion-cli` enables the feature.
- **No retries** anywhere in the nextest config, so a flaky test cannot pass on a second try.
