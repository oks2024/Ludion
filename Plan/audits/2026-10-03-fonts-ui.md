# Audit: fonts, text layout and screen UI (2026-10-03)

Report only. No code was changed.

**Scope.** The `ludion-font` crate (`src/lib.rs`, `src/layout.rs`, `src/bake/{mod,outline,kerning,
geometry,pack,sdf,coverage}.rs`, `tests/`), the `kind: font` / `kind: font-source` / `kind: fonts`
formats in `ludion-scene` (`font.rs` validation), the engine side (`ludion-engine/src/ui.rs`,
`fonts.rs`, `font_sheet.rs`, the text and UI arms of `extract.rs`, `scene_check.rs`'s font passes,
the text-relevant `components.rs` types), the renderer's text paths (`render.rs` `build_text_draws`,
`build_ui_batches`, `push_ui_text_verts`, `font_bind_group`; `shaders/ui_text.wgsl`), the CLI bake
(`generate_atlas.rs` font branch, `check_scene.rs` font wiring), the drift gate
(`scripts/atlas-drift.mjs`), the consumers (breakout's pause menu, vigil's `hud.rs`), the docs
(`docs/fonts.md`, `screen-ui.md`, `ui-list.md`, `components-ui.md`, `dev-docs/ludion-font.md`), and
licensing (`THIRD-PARTY-NOTICES.md`, `licenses/`, the committed faces). Plans read:
`Plan/font-assets.md`, `Plan/phase-14-ui.md`, `Plan/ui-widgets.md`. Revision `d9a487f5`; some docs
files carry another instance's uncommitted edits, and the docs findings below were checked against
the working tree.

## Overall assessment

This is a well-built feature. The "one `layout()`" claim holds: `measure_ui_text`, `wrap_ui_text`,
`resolve_ui_list`, `list_hit`, extract's `UiText`/`UiList`/`Text` quads, `bounds.rs` and the
`render --font` specimen all call `ludion_font::layout`, and the renderer only draws `GlyphQuad`s
as it receives them. The bake is designed for determinism. It flattens curves with a fixed number of
segments, sizes texel boxes with integer arithmetic, packs glyphs in code-point order and never calls
a transcendental. Two PNG-hash canaries and the `atlas-drift` gate, which runs in both CI and
`check.mjs`, back that up. Validation is thorough and every error carries an `L125x` code. The
audit found no High finding. The one Medium is a measured-versus-drawn gap in `UiList` that vigil
has already hit and works around in game code. The Lows are leftover duplicate 8×8 label tables,
per-frame allocation, `\r`/`\t` handling, stale docs, an easy-to-misuse public helper and a gap in
how the drift gate finds its files.

## High

None.

## Medium

### F1 — A `UiList` title or item containing `'\n'` draws extra lines over the rows below, while measurement and `list_hit` count it as one row · Medium · [verified]

**Evidence.**
- `crates/ludion-engine/src/extract.rs:900-907` lays out each list line with
  `ludion_font::layout(face, text, list.size, 0.0)`. `layout` treats `'\n'` as a hard break
  (`crates/ludion-font/src/layout.rs:345-346`), and `quads()` steps `pen_y += size` for each extra
  line (`layout.rs:407-411`). The item's second line therefore lands exactly on the next row.
- `measure_ui_list` (`crates/ludion-engine/src/ui.rs:369-380`) counts one row per item
  (`ui_list_lines(list).count()`). `list_hit` (`ui.rs:463-485`) maps row `k` to item `k`.
- `UiList::validate_semantics` (`components.rs:2698-2711`) checks only `size`. Nothing rejects or
  normalizes a newline in `title` or `items[*].text`. The `L1256` pass explicitly skips `'\n'`
  (`scene_check.rs:419`).
- vigil has already hit this and works around it in game code. `games/vigil/src/hud.rs:404-414`,
  `single_line()`, says: "a `'\n'` inside an item's text is drawn over the row below it and shifts
  every line's index away from the item it belongs to". Every vigil ware and offer label goes through
  it.

**Why it matters.** The phase-14/font-assets promise is that "the measured block and the drawn one
cannot disagree", and here they do. The panel background is also measured one row short, so the
overflow line draws outside it. Every game would have to rediscover vigil's workaround.

**Failure scenario.** A shop item is built as `format!("{label}\n{cost}")`. Its cost line draws on top
of the next item. A click on that overlapping text returns the next item's index, so the player buys
the wrong ware. The `UiList` with its `items` is hashed state, so this replays faithfully, wrong
purchase included.

**Fix.** Make the rule "one item = one row" true in the engine. Either (a) lay out list lines with
`'\n'` folded to a space in extract and treat it the same way in measurement (one shared helper, so
the two cannot diverge), or (b) add an `L####` warning in `UiList` validation and a once-per-entity
runtime diagnostic for runtime-built strings. Then delete vigil's `single_line` (its comment also
mentions a pointer hit test that vigil does not have).

## Low

### F2 — `'\r'` and `'\t'` are ordinary glyphs to `layout()`: CRLF text gains a trailing tofu glyph, or a blank cell, per line, and a tab is neither whitespace nor a break · Low · [verified]

**Evidence.** `layout.rs:346` and `:349` split only on `'\n'`, and words split only on `' '`
(`layout.rs:272`). A `'\r'` stays at the end of each line and a `'\t'` stays inside a word. Both fall
through to the notdef glyph: a drawn `.notdef` box on a baked face, a blank 8-unit advance on the
embedded face (`lib.rs:104-108`).

**Why / scenario.** A runtime string read from a CRLF file, or produced by a `"\r\n"` YAML escape,
draws a tofu box at every line end on Inter. On the 8×8 face the block measures one cell wider per
line, so a right- or centre-anchored label shifts by half a cell. `check-scene` does flag authored
`\r`/`\t` as `L1256`, but only for table faces and never for runtime strings.

**Fix.** In `layout()`, treat `"\r\n"` and a lone `'\r'` as a line break, and either break words at
`'\t'` like a space or document that a tab draws notdef. Add one layout test for each.

### F3 — Three hand-maintained 8×8 label glyph tables survive beside the embedded `kind: font` face · Low · [verified]

**Evidence.** `crates/ludion-engine/src/voxel_sheet.rs:800-848` (`GLYPHS`, whose comment says it is
"duplicated verbatim rather than importing that face"), `crates/ludion-engine/src/sprite_sheet.rs:2419-2466`
(`EXTRA_GLYPHS` "extends" it) and a third table in `crates/ludion-gen/src/sheet.rs` (module doc,
lines 14-17). `font_sheet.rs:22` burns its labels with these tables, not with the face it is
rendering. `ludion-gen`'s stated reason, "The renderer's own 8×8 font is GPU-side and crate-private",
is stale: the face now lives in the pure, wgpu-free `ludion-font` (`EMBEDDED_PNG`, `FontFace::embedded`).
The same line appears in `dev-docs/ludion-gen.md:113`.

**Why it matters.** Decision 11 made the 8×8 face data so that there would be one face (Pillar 6).
These tables are a second and third copy, and their alphabets already differ: the voxel table is a
subset and the sprite table adds `F P Q W X Z` and punctuation. A glyph fixed in one copy stays wrong
in the others.

**Fix.** Give the CPU sheets one stamping helper over `FontFace::embedded()` plus the decoded
`EMBEDDED_PNG` (`font_sheet.rs`'s test already decodes it), or one shared `layout()` + quad stamp.
Then delete the tables and correct the stale rationale.

### F4 — Every frame re-lays out unchanged text and allocates strings that only introspection reads · Low · [verified]

**Evidence.**
- `ui_text_draw` (`ui.rs:202-212`) builds `joined_lines(&laid)`, a `Vec<String>` plus a `join`, for
  every visible `UiText` on every frame. The renderer never reads `UiInstance::Text::text`
  (`ludion-renderer/src/scene.rs:591`: "introspection only").
- The `UiList` arm (`extract.rs:900-913`) calls `text.to_string()` per line per frame. It also lays
  out every item twice per frame: once in `resolve_ui_list → measure_ui_list` and once for the quads.
  `list_hit` measures the list twice per call (`ui.rs:471-473`).
- `wrap_paragraph` clones `current` and re-measures the whole candidate line for every word
  (`layout.rs:286-292`), so wrapping costs O(words × line length) binary searches per frame.
- `report_font_faults` runs every tick (`engine.rs:1086`). It clones every component's `font` string
  before filtering (`fonts.rs:255,260,265`: `c.font.clone().filter(unknown)`), and for each standing
  fault it allocates the message and key on every tick (`fonts.rs:247-249`) before the latch rejects
  them.

**Why it matters.** None of this hurts today. vigil changes its HUD strings only when they change,
and its UI is small. But these costs grow with every text-heavy screen (prose, invoices, long lists)
and land on the 60 fps budget even when nothing moved.

**Fix.** Use `filter(...).cloned()` order in `report_font_faults`, and key the latch check before
building messages. Build the introspection string lazily, or drop it in favour of the component
text. In `UiList`, reuse the per-item widths measured for the block when drawing. Caching layout
across frames is not worth it yet.

### F5 — Several docs still describe text as the fixed 8×8 uppercase face · Low · [verified]

**Evidence.**
- `docs/ui-list.md:131-132`: "The glyph set is `Text`'s 8×8 uppercase bitmap atlas: lowercase folds
  to uppercase…". This is stated without qualification, although `UiList.font` exists and the same
  page links `ludion docs fonts`.
- `docs/screen-ui.md:12`: "`UiText` (a run of the same 8×8 bitmap font `Text` draws…)".
- `docs/components-ui.md:15` describes `UiText` wrapping as "breaking on spaces and hard-breaking an
  overlong word" and leaves out the `-`/`—` breaks that `screen-ui.md` documents.
- Code docs: `components.rs:1782` ("A run of bitmap text") and `ludion-renderer/src/scene.rs:586`
  ("screen-space bitmap text"), although both paths draw SDF faces.

**Why it matters.** Agents read these topics before authoring. A model told that lowercase folds to
uppercase will keep writing uppercase strings for a proportional face, or will distrust a correct
render.

**Fix.** Qualify each line as applying to the embedded face, and point to `ludion docs fonts`.
`embedded-docs/` must be re-mirrored with `check.mjs --fix`. Coordinate with whoever owns the
in-flight edits to these files.

### F6 — `resolve_ui_text` measures the raw string and ignores `wrap_width`; the `&UiText`-aware geometry is crate-private · Low · [verified]

**Evidence.** The public `resolve_ui_text(face, anchor, offset, text: &str, size, viewport)`
(`ui.rs:231-242`) calls `measure_ui_text` with no wrap. The function that wraps, anchors and draws
from one layout, `ui_text_draw(face, &UiText, viewport)` (`ui.rs:202`), is `pub(crate)`.
`docs/screen-ui.md` tells games to call `wrap_ui_text` first and then measure the result.

**Scenario.** A game hit-tests a wrapped, centre-anchored `UiText` button with
`resolve_ui_text(face, ui.anchor, ui.offset, &ui.text, ui.size, viewport)`. It gets the rect of one
long unwrapped line, centred differently from what is drawn, so clicks on the second line miss.

**Fix.** One way: make the public helper take `&UiText`, wrap internally and return the block rect,
sharing `ui_text_draw`'s layout so the two cannot drift. `list_hit` already works this way for
`UiList`.

### F7 — `atlas-drift` finds font pairs from their outputs, so a source with no committed doc, or a doc that lost `generated_from:`, is never checked · Low · [verified]

**Evidence.** `scripts/atlas-drift.mjs:31-46,52-58` walks `*.font.yaml` and follows each file's
`generated_from:`. A `*.font-source.yaml` whose output was never committed, was deleted, or had its
`generated_from:` line removed is invisible to the gate, which then passes without checking anything.
The loader accepts a doc with no `generated_from:` as authored, as the embedded face is
(`font.rs` validation does not require it).

**Why it matters.** "Generated content is write-only" depends on this gate. If an editor strips the
provenance line, a hand-edited face (changed advances, and therefore changed `list_hit` results and
replays) stops being checked, and nothing reports it.

**Fix.** Also walk `*.font-source.yaml` (and `*.atlas-source.yaml`) and require that each one has a
sibling output naming it back. Alternatively, make the CLI's `--check` fail when the output exists
without the provenance line.

## Checked and healthy

- **One layout path.** Every measure, wrap, hit-test, extract, bounds and specimen call goes through
  `ludion_font::layout`. No per-character pen loop is left in the renderer or the engine.
  `legacy_cell_parity.rs` and `font_layout_parity.rs` pin the 8×8 face bit for bit.
- **Wrap correctness.** The last word is always kept (`lines.push(current)`), an overlong word
  hard-breaks with at least one glyph per line, hyphen and em-dash breaks rejoin without a space,
  NBSP never breaks, empty and all-space text gives zero lines, kerning is counted inside candidate
  widths and is never applied across a line break, and `limit_units` is floored, so a wrapped line
  never exceeds `wrap_width`.
- **No UTF-8 panics.** Everything works on `char`s. A missing glyph advances by notdef and draws a
  `.notdef` quad only if notdef has ink. CJK, emoji and combining marks degrade to notdef with no
  panic; Tier B shaping is a recorded deferral.
- **Measure equals draw.** `UiText` and `UiList` (newline-free, see F1) hit-test against the same
  `RenderExtent` the extract uses. breakout proves a proportional `list_hit` through record and
  replay, including at a non-default extent.
- **Bake determinism.** No `mul_add` or transcendentals. Curves flatten with a constant number of
  segments, texel boxes use integer `floor_div`/`ceil_div`, glyphs pack in code-point order with
  notdef last, the gutter keeps bilinear SDF sampling from bleeding between glyphs, and the bake is
  single-threaded. The Inter and Silkscreen PNG-hash canaries live in `tests/bake_atlas.rs`.
  `generate-atlas --check` byte-compares both files and runs in `check.mjs`, CI and TeamCity.
  `skrifa`/`harfrust` are pinned with `=`.
- **Validation and error UX.** `kind: font` checks code-point order, rect-in-atlas, unit ranges,
  positive line height and the spread/mode pairing. A source `name` must be a plain stem. A malformed
  TTF is `L1252`, never a panic. An atlas whose size disagrees with its document is `L1255` and the
  frame fails rather than sampling the wrong texels (`extract.rs:2640-2653`). An unknown face name
  is a `check-scene` error with the nearest-name suggestion, and at runtime it is reported once and
  falls back to the default face for both drawing and measurement.
- **Hash neutrality.** `font` is skip-serialized at `None`. `FontLibrary` is an `Arc`, never hashed or
  snapshotted, and a reload is refused while recording.
- **Draw order.** The UI sorts by the pinned `(order, EntityId)` key; text batches split on a face
  change; the embedded face samples nearest, SDF faces linear, bitmap faces nearest.
- **Licensing.** Inter 4.1 and Silkscreen (OFL-1.1, no Reserved Font Name) have their licence beside
  every TTF copy, including breakout's. The `licenses/` copies are byte-identical.
  `THIRD-PARTY-NOTICES.md` has a Fonts section. `skrifa` (MIT/Apache-2.0) and `harfrust` (MIT) sit
  behind the CLI-only `bake` feature, and the runtime never parses a font.
