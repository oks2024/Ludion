# Audit: map generation, map sources, tilemaps and the map drift gate (report only)

**Scope.** Rev `19ef84a3`. Files covered: `crates/ludion-scene/src/map.rs` (the `kind: map` /
`kind: map-kit` parsers and the pure `generate`), `crates/ludion-cli/src/generate_map.rs`,
`crates/ludion-cli/src/map_check.rs`, `crates/ludion-cli/tests/map.rs` and its fixtures,
`crates/ludion-scene/src/map_tests.rs`, `scripts/map-drift.mjs` and its `check.mjs`/`ci.yml` wiring,
the `Tilemap` component (`crates/ludion-engine/src/components.rs:1930-2096`, extract at
`crates/ludion-engine/src/extract.rs:2117-2163`), vigil's map sources and kit
(`games/vigil/scenes/*.map.yaml`, `city.kit.yaml`), the town-square generator
(`games/vigil/art/town/square/build-square.mjs`) as a composed fragment, and the docs
`docs/map-authoring.md`, `docs/map-check.md`, `docs/tilemaps.md`. I checked behaviour against scratch
copies outside the repository with the existing `ludion` binaries. I ran `generate-map --check` and
`map-check` read-only on the vigil maps. Neither writes anything (`generate_map.rs:150-201`,
`map_check.rs` has no write).

## Overall assessment

The generator is sound where it matters most. Output is byte-deterministic and platform-free:
`generated_from` is a bare file name, the arithmetic is plain f64, entity order is fixed, and an emit
→ parse → emit self-check runs before every write. All 18 vigil maps regenerate up to date. A change to
a fragment or the kit is caught, because the drift gate regenerates from the live inputs. The defects
sit at the edges. An empty `rows:` silently drops every marker, a trap vigil already documents in a
code comment. The drift gate finds work only through outputs, and it leaks a 4.7 MB temp directory
on every run (1.4 GB on the reference box today). `map-check`'s gate lint assumes the grid edge is the
district wall, which the new fragment-composed districts break. The rest are latent kit semantics,
error-UX gaps and stale text.

## High

None.

## Medium

### T1 — An empty `rows:` silently drops every marker; generate-map exits 0 and map-check says nothing · Medium · [verified]

**Evidence.** `check_grid` returns `None` for an empty grid without pushing a diagnostic
(`crates/ludion-scene/src/map.rs:1699-1701`). `generate` runs both the grid pass and the marker pass
only under `if let Some(width) = width` (`map.rs:1145`). A ragged grid at least raises `L1019`, but
an empty grid raises nothing. `rows: []` is legal text: the parser accepts an empty sequence, and the
crate's own tests use it (`map_tests.rs:480`, `:496`). In scratch, a map with `rows: []` and two
markers printed `generated 0 entities` and exit 0, and wrote `entities: []`. `map-check` prints
`grid: empty (no rows)` and returns before the marker table (`map_check.rs:988-993`). vigil
already hit this. `games/vigil/scenes/district-breach.map.yaml:9-10` pads a 24×20 all-space grid
"only [to give] the markers a frame … (an empty `rows:` drops every marker)". The engine docs do not
mention it.

**Why it matters.** The fragment-composed district (town square plus gameplay markers) is now the
city's direction (a private plan). The natural way to write "no grid" loses every
gate, anchor and site without an error.

**Failure scenario.** An agent composes a new district from a generated fragment with `rows: []`.
generate-map succeeds, and the scene has the fragment but no gates and no `from-*` anchors. The first
sign is an `L1027` in a neighbouring map, or a runtime `L3019`.

**Fix.** Raise `L1023` (or a new code) for any marker when the grid is empty, naming the missing
frame. Better, let a marker-only map omit `rows` and bound markers by an explicit `bounds:` or by the
markers themselves, so the all-space padding grid goes away.

### T2 — The drift gate discovers work from outputs, so a map with no committed scene is never checked · Medium · [verified by reading]

**Evidence.** `scripts/map-drift.mjs:84-87` enters only through a committed file's
`generated_from:`. A `*.map.yaml` is walked (`:59`) but skipped, because it has no such field. No step
asserts that each `*.map.yaml` has an output, or that the output sits at the default path
`generate-map` would write. `map-check`'s cross-map link check also prefers the sibling
`<stem>.map.yaml`, generated in memory, over the committed scene (`map_check.rs:910-916`). So a
missing scene passes there too. This is the series-wide pattern (`master-audit.md` "Drift gates
discover work from outputs").

**Why it matters.** Both gates stay green on exactly the state that breaks the game: a source whose
scene was never generated or committed, or was deleted.

**Failure scenario.** An agent adds `district-x.map.yaml` and gates to it from two neighbours, then
commits without running `generate-map`. `map-check` is green (L1027 resolves `from-*` against the
in-memory map) and `map-drift` is green (nothing to discover). Crossing the gate fails at runtime
because `district-x.yaml` does not exist. The same applies after a `git mv` of a generated scene: the
gate keeps comparing the renamed file, and the remedy it prints (`generate-map <map>`) writes the
old name.

**Fix.** Enumerate sources. For every `*.map.yaml` under the scan roots, require the default output
to exist with `generated_from` naming it and to be byte-identical. Then require every
`generated_from: *.map.yaml` scene to be that map's default output.

### T3 — `map-drift.mjs` never deletes its temp directory: 313 leaked copies, 1.4 GB, on the reference box · Medium · [verified]

**Evidence.** `scripts/map-drift.mjs:78` makes a `mkdtempSync` directory, and `:134-135` writes every
regenerated scene into it. There is no `rmSync` on any path. Today `%TEMP%` holds 313
`ludion-map-drift-*` directories of about 4.7 MB each, 1.4 GB in all. The default `check.mjs` lane
runs the gate on every invocation. A `--check` mode that needs no temp file already exists
(`generate_map.rs:150-201`).

**Why it matters.** The reference box already fills its disks during gates (see the box notes), and
this gate grows by one copy of every generated district per run.

**Fix.** Call `ludion generate-map <map> --out <committed scene> --check` and drop the temp dir.
`--check` writes nothing and exits non-zero with a DRIFT line. If a temp is kept, wrap the run in
`try/finally { rmSync(tmp, { recursive: true }) }`.

### T4 — `L1028` reads the grid edge as the district wall, so every fragment-composed district gets bogus "gate sealed" warnings that the N1 fix will not clear · Medium · [verified]

**Evidence.** `has_perimeter_gap` accepts a gap only on a cell with `grid.is_edge(r, c)`
(`map_check.rs:787-793`; `is_edge` at `map.rs:212-216`). `district-breach.map.yaml` uses a 24×20
void frame larger than the playable square, so its gates sit at (c11,r4), (c13,r16) and (c5,r9).
None of these cells or their neighbours is on the frame's edge. Running `map-check` on it prints all
three `L1028`s, and the result is geometric: no occupancy fix can remove them. spatial-nav N1 put
these warnings down to the missing prefab colliders, but the root cause here is separate. For the same
reason, once N1 lands, the void beyond the bound colliders will read as walkable cells the anchor
cannot reach. That puts "unreachable"/`?` noise into the counts.

**Why it matters.** Every district built in the town-square style inherits three permanent false
warnings. Warnings that are always present teach agents to ignore `L1028`, which is the lint that
catches a real gate on the wrong side of a wall.

**Fix.** Define the gate check by reachability, not perimeter. A gate's approach cell must be
reachable from the anchor, which `Traverse` already computes. Alternatively, let a map declare its
playable bounds, and treat void cells as outside: exclude them from walkable and unreachable
counts unless something occupies them.

## Low

### T5 — A merged primitive's authored collider is discarded: an `aabb` is inflated to the full rect and a `circle` stays one circle for the whole run · Low · [verified]

**Evidence.** `scale_collider` (`map.rs:1685-1692`) replaces any `aabb` with
`[cols*cell/2, rows*cell/2]` and leaves a `circle` as authored. In scratch, an `aabb: [0.25, 0.25]`
wall over a 4×1 run at `cell_size: 2` emitted `half_extents: [4.0, 1.0]`. A `circle: 0.5` over an
8×2-unit run emitted one radius-0.5 circle at the centre. `docs/map-authoring.md` says "one clean
collider per run" but never says the authored size is ignored. vigil's only merged collider is
exactly cell-sized (`city.kit.yaml` `#`), so nothing is affected today.

**Fix.** Reject `circle` with `merge: true` (`L1022`), and scale the authored `aabb` by the rect
(or reject a non-cell-sized `aabb`). Document whichever rule is chosen.

### T6 — The reserved void glyph is not reserved: a kit that defines `" "` makes every void cell emit · Low · [verified]

**Evidence.** `check_grid` exempts `' '` from the glyph check (`map.rs:1723`), but `emit_grid`
iterates every kit tile, including `" "`, with mask `glyph_at == ' '` (`map.rs:1263-1281`). In
scratch, a kit with a `" ":` tile turned a two-space row into `hole-r000-c000` and `hole-r000-c001`.
The docs say a space "emits nothing" (`docs/map-authoring.md` "Grid orientation").

**Fix.** Reject a `" "` tile key with `L1020` ("the space is the reserved void glyph").

### T7 — A fragment's `physics:` block (and `seed`) is silently dropped, and a map cannot declare one · Low · [verified]

**Evidence.** `generate` builds the scene with `physics: None` (`map.rs:1175-1181`). Fragments
contribute only `entities` (`:1139-1141`). `MAP_KEYS` has no `physics` (`map.rs:53-64`). In scratch,
a fragment that passes `check-scene` with `physics: { space: planar, gravity: … }` composed into a
scene with no `physics:` block. No vigil scene uses one today. A game on `ludion-physics`
(`physics.layers`, gravity) cannot generate its districts.

**Fix.** Either error when a fragment carries `physics:` (pointing at the dropped block), or add a
map-level `physics:` key that is emitted verbatim.

### T8 — Generated coordinates carry f64 arithmetic noise the engine never holds · Low · [verified]

**Evidence.** `rect_center` and the merged scale/collider are computed in f64 (`map.rs:224-229`,
`:1334`, `:1688`) and emitted with ryu's f64 formatter. In scratch, `cell_size: 0.7` with origin
`0.1` emitted `1.0499999999999998`. The engine reads f32, so the value it holds is not the value
the file states. Byte-identity is unaffected, because the arithmetic is deterministic IEEE. vigil's
`cell_size: 4.0` and integer or half origins keep every value exact today.

**Fix.** Round each emitted coordinate through `f32` before it enters the `Value`. That is
"quantize at the source", and it makes the text match what the engine holds.

### T9 — Error UX: `L1025` carries no pointer or origin, and a `--check` drift reports as `L1021` "malformed map" · Low · [verified by reading]

**Evidence.** `check_name_collisions` (`map.rs:1858-1876`) names the duplicate but not which
fragment, grid primitive or marker produced either copy, and sets no JSON Pointer. On
`district-breach` that is a search across 298 fragment entities and 19 markers. `check_one` reports
drift under `code::MAP_DOCUMENT_STRUCTURE` (`generate_map.rs:169-180`), so `ludion explain` describes
a structural parse error.

**Fix.** Track an origin per emitted entity (fragment path plus index, `/markers/<i>`, or
`/rows/<r>`) and print both origins. Give drift a code of its own, or reuse the scene-I/O code.

### T10 — The `.mjs` hand-off does not check that the generator produces the scene, unlike the `.rs` hand-off · Low · [verified by reading]

**Evidence.** For `generated_from: *.rs`, `map-drift.mjs:94-104` requires the named test to mention
the scene's basename. For `*.mjs`, it only runs `--check` once per generator (`:110-121`).
`build-square.mjs --check` compares only `town-square.yaml` (`build-square.mjs:497-501`). So any
other scene that claims `generated_from: ../art/town/square/build-square.mjs` passes unexamined. The
generator itself writes such files on request: `--sim-only` and `--colliders` variants must sit in
`games/vigil/scenes/`, and `SQUARE_FIGURE=1` writes `_square-figure.yaml` there. A hand-edited or
stale copy of one of these that gets committed is never compared. `prefabs.mjs --check` does flag
unproduced files in its own directory (`prefabs.mjs:159`). `build-square.mjs` has no equivalent.

**Fix.** Have `--check` generators print the paths they verified, and require the scene to be among
them. That is the `.rs` rule, made exact.

### T11 — `Tilemap.cell_size` accepts zero and negative values · Low · [verified]

**Evidence.** `Tilemap.cell_size` has no schema floor (`components.rs:1931-1933`), unlike
`MeshGrid.cell_size`'s `exclusiveMinimum: 0` (`components.rs:2162`). The semantic validator never
looks at it (`components.rs:1996-2063`). A scratch scene with `cell_size: -2.0`, and another with
`0.0`, both passed `check-scene` as OK. Extract then mirrors the grid or collapses every cell to a
point (`extract.rs:2124-2138`), and `world_to_cell` divides by zero (`components.rs:1989-1993`).

**Fix.** Add `#[schemars(extend("exclusiveMinimum" = 0.0))]` as `MeshGrid` does.

### T12 — The `docs/tilemaps.md` system example misreads off-grid movers · Low · [verified by reading]

**Evidence.** The example clamps with `glyph_at(col.max(0) as usize, row.max(0) as usize)`
(`docs/tilemaps.md`, "Reading a tilemap from a system"). A mover at column −1 therefore reads column
0's glyph and is "snapped" to `cell_to_world(origin, -1, row)`, outside the grid. The comment just
above it says `glyph_at` handles out-of-range cells, and the clamp defeats that. Examples are the
primary documentation format, so this pattern gets copied.

**Fix.** `usize::try_from(col).ok().zip(usize::try_from(row).ok()).and_then(|(c, r)| map.glyph_at(c, r))`.

### T13 — Stale and schedule-shaped text around the map tooling · Low · [verified]

- `docs/map-authoring.md` (markers block) says a marker `name:` is "required, globally unique". It
  is optional (`map.rs:113-114`, `derived_name` at `:133-138`), and `L1032` exists precisely because
  unnamed markers fall back to `<kind>-<index>`.
- `crates/ludion-cli/src/generate_map.rs:8` names the drift gate "`scripts/check.mjs` `mapDrift`".
  No such identifier exists; the gate is `scripts/map-drift.mjs`.
- Schedule comments, which CLAUDE.md forbids: `scripts/map-drift.mjs:8` ("Vacuous today (Wave 3
  commits the first generated district)", which is false: 18 scenes are gated) and
  `crates/ludion-scene/src/map.rs:20-23` ("the CLI (Wave 2)", "Wave 2's `map-check`").
- `docs/map-check.md:41` says the probe is a "sphere". It is a 2D circle (`map_check.rs:303-310`).

## Checked and healthy

- **Byte-identity.** Entity order is fixed (fragments → grid sorted by `(r0, c0, seq)` → markers,
  `map.rs:1139-1166`). Names derive from coordinates. Variants come from a per-cell splitmix of
  `(seed, row, col)`, independent of draw order. The emitter is ryu shortest f64 with no f32 widening,
  so scene-text S1's `scene.save` path is not involved. `generated_from` is a bare file name, with no
  path separators. emit → parse → emit is asserted before each write (`generate_map.rs:225-240`).
  `generate-map --check` on all 18 vigil maps reports up to date.
- **Composition invalidation.** The gate regenerates from the live kit and fragment files. An edit to
  `hud.yaml`, `env-night.yaml`, the kit, or a regenerated `town-square.yaml` fails every composing
  scene, and the failure message gives the remedy.
- **Validation.** Ragged rows (`L1019`, per row, with a pointer), unknown glyphs (`L1020`, once per
  glyph with row and column), f32-overflowing numbers (read as ±inf by `fields::engine_number`,
  then rejected; tested), out-of-bounds or non-finite marker positions (`L1023`), footprint misfits
  (`L1026`, once per row), and merge+footprint clashes are all handled. Kit and fragment load errors
  are collected across all files in one run. Unknown keys get nearest-match help. Unicode is counted
  per `char` throughout, consistently.
- **Scale.** A 400×400 generated grid (160k entities) takes 7.4 s, and 800×800 (640k) takes 29 s:
  linear, with no quadratic blow-up in practice despite `chars().nth`. The vigil set (largest
  80×80) regenerates in about 1.4 s.
- **Prior items.** July's D2 (`single_char` duplicated) is fixed: `map.rs` imports
  `ludion_core::text::single_char`. `map-check`'s `L1028`/`L1029` now carry pointers (July D4).
- **map-check** writes nothing. Its walker resolves flag → kit → default, with the source printed.
  `L1027` is its only error and the only check that sets the exit code. `L1031` runs without
  `--traverse`.
- **`map-drift`** is mirrored in `check.mjs` (`DRIFT_GATES`) and `ci.yml:145-147`, and runs after
  `import-sync`, which `build-square.mjs` needs.

## Suggested order of work

1. **T3.** Switch `map-drift` to `generate-map --check`. This is a one-line fix that also stops the
   disk leak.
2. **T2.** Enumerate `*.map.yaml` sources in the same pass, the series-wide fix applied to maps.
3. **T1.** Error on markers with an empty grid, then consider a marker-only map with explicit bounds.
   That also removes the padding grid T4 trips on.
4. **T4.** Make the `L1028` check use reachability (together with spatial-nav N1, since both change
   `map-check`'s occupancy story).
5. **T5, T6, T11.** Kit and tilemap validation: small, local, and each one closes a silent-wrong-output
   case.
6. **T9, T10, T7, T8, T12, T13** as convenient.
