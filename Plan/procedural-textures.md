# Plan: Procedural textures — a text recipe that produces a PBR map set

> **Status:** Wave 0 (the spike) passed its verdict, Go, 2026-10-24; Wave 1 (the op library) is in progress. Decided 2026-10-23. Later waves are recorded with
> triggers.

## Why

Ludion consumes five PBR maps per material (`Plan/textured-pbr.md`), but has no way to *make* them:
textures arrive only through `ludion import`. The reference game's Blender kits fill the gap with
node-based Cycles materials baked per object. A node graph is opaque to an agent: it cannot read,
diff or iterate on it. An LLM-first engine wants the texture to be text — a recipe the agent writes,
renders, looks at and corrects — with the maps generated from it.

The claim that such a recipe reaches "really good results" is empirical, so a spike gates the full
plan (the `Plan/cooked-assets.md` Wave 0 precedent).

## Settled decisions (2026-10-23)

1. **Spike first, then the full plan.** A minimal core plus reference materials and the user's
   verdict gate everything below Wave 0.
2. **Tileable materials first; mesh-aware (Painter-like) texturing is a later wave.**
3. **A declarative YAML recipe** (`kind: texture`, `*.texture.yaml`): named steps forming a DAG,
   parametrized sub-recipes. Data, not code — no Rust per texture, no expression language. This
   keeps Pillar 4 (text is the source of truth) and the "Rust is the only Turing-complete layer" rule.
4. **Style-neutral.** Realistic, stylized and hand-painted must all be reachable from the same
   engine. Specialized per-style generators are a fallback, never the goal.
5. **Two layers.** Style-agnostic Rust primitives, including the hard generators (tile sampler,
   flood fill, distance field, height → normal / AO / curvature); and macros as parametrized
   sub-recipe files in an engine stdlib that a game references or overrides. Style lives in data,
   never in the engine.
6. **CPU, f32, bit-exact across architectures** (`ludion_core::math` libm, `ludion_core::par`).
   Recipe → PNG is a pure function. Each resolution is separately bit-exact.
7. **One external-image input op**; the core library stays fully procedural.
8. **Outputs are exactly Ludion's five maps** (emissive only when the recipe authors it) plus a
   16-bit linear height map.
9. **Committed, write-only, drift-gated.** `ludion texture build --check` compares regenerated bytes
   to the committed PNGs (the `mesh apply` precedent). An op-library change shows as a reviewed
   diff of generated files, never a silent re-texturing.
10. **Tile units (0..1), never pixels; tileable by construction** (periodic generators, wrap-around
    filters), so a recipe is resolution-independent.
11. **Crate `ludion-texgen`, linked by `ludion-cli` only** (the `ludion-cook` precedent). No game
    binary or `ludion-engine` links it. A pipeline verb satisfies the parity gate; no wire command,
    no editor surface (`CLAUDE.md` Non-negotiables).
12. **Verbs: `ludion texture build | check | vendor`.** `build` writes the maps and a JSON report
    (`--json`); `check` validates without writing; `vendor` copies a stdlib recipe into the project
    to override it.
13. **The stdlib is embedded in the binary, referenced with the `std:` prefix.**
14. **Validators.** An engine PBR-plausibility set (albedo range, roughness/metal sanity, normal
    unit length, tiling seam, periodicity) plus optional project rules in TOML, in the shape of
    `image-stats --check`. The reference game's lab rules can move into it.
15. **Kit consumption, spike.** Blender samples the generated sets as images and the existing
    per-object bake still runs. No engine change.
16. **Spike feedback loop.** A Ludion-rendered preview (sphere, plane, rounded cube under the
    Environment and one key light), a per-map sheet, per-step thumbnails, a 2×2 tiling view,
    the numeric validators and the JSON report. Comparison against a reference image is deferred.
17. **Anti-tiling in the spike is measured, not solved:** the tiling view and a periodicity
    validator expose repetition; bake-time macro variation on the kit piece covers it if needed.
18. **Speed budget (~40-step recipe, feedback included):** ≤2 s at 512², ≤10 s at 1024²,
    ≤40 s at 2048². Measured indicatively on a non-pinned dev machine during the spike; the
    pinned-M4 measurement is owed (`Plan/owed.md`).
19. **Revisits `Plan/textured-pbr.md` decision 1 and its "no texture-authoring surface" fence.**
    A text recipe is diffable source with generated, drift-gated maps, which removes the fence's
    reason; both places carry an amendment line.
20. **W0 verdict: Go (2026-10-24).** Wave 1 builds the op library that the spike's missing-ops log
    names and re-authors the reference materials to measure the gain. Seed variants and adopting
    texture sets in the reference game's kits stay deferred under their triggers.
21. **A `layer` step.** One mask drives several output maps (colour, roughness, metallic, height)
    in one step. It extends the declarative format; there is still no expression language and no
    node graph. Its exact shape is settled in Wave 1 and recorded here.

## Waves

### Wave 0 — the spike

- `ludion-texgen` core: recipe parse, DAG evaluation, f32 tile-unit image buffers, the hard
  generators, the `std:` stdlib.
- `ludion texture build | check | vendor`, with the drift `--check`, the validators and the JSON
  report.
- The feedback loop of decision 16.
- Three reference materials: **cobble, oak planks, painted/rusty iron**. One is also restyled —
  **cobble realistic vs hand-painted** — by changing only recipe data and stdlib parameters.
- A log of iterations-to-result per material and of every missing op. The full plan's op list
  comes from this log, not from guesswork.
- One real kit piece of the reference game, end to end, beside its node-material twin (a small
  kit hook maps a generated set at the texel-density scale → bake → import → in-game). Detail in
  a private plan.
- The user's verdict sitting, judging each material against the current node-material bake and a
  CC0 photoreal reference on one preview rig.

**Exit — the verdict rule:**
- **Go** if at least 2 of 3 materials are at least as good as their node-material bake *and* the
  restyle reads as a distinct style.
- **One of three:** one targeted follow-up wave driven by the missing-ops log, then judge again.
- **None:** park. The crate is deleted; nothing outside it depends on it.

### Wave 1 — the op library

Driven by the Wave 0 missing-ops log and the kit piece's findings.

- **Layout:** a per-row random offset in `tile_sampler`; a uniform gap width on non-square cells;
  per-instance pattern scale; layout params exposed on `std:planks` and `std:cobbles`; a rounded
  (facet-free) cobble profile.
- **Tone and filter:** posterize; a band/rim mask from a height; hue/saturation shift (palette
  re-hue); anisotropic (stretched) noise; directional blur/smear.
- **The `layer` step** (decision 21).
- **Seeds and validators:** a seam-safe seed search guided by the validators; a `repetition_peak`
  that does not flag directional patterns (the long-grain false positive).
- **Re-authoring:** rebuild the four reference materials and the kit piece's wood with the new
  ops, logging steps and iterations before and after.

Also met on the kit piece: no recipe params for layout (the recipe was vendored instead of
referenced), no way to re-hue a palette without editing colour stops, and a constant board that
needed `constant` stand-ins for `board_id` and `face`, so the board and gap ops were bypassed by hand.

**Exit:** every op shipped with a test and a `texture-ops` entry; the re-authored materials' drift
checks are green; the before/after log is in Status. Nothing in the Exit waits on a human.

### Later waves — deferred, with triggers

Recorded so the decision is made from analysis, not under pressure. Wave 0 passed; these still
wait on their own triggers.

- **Seed variants** — one recipe, N seeded outputs. Trigger: the periodicity validator or the
  user's eye reports visible repetition on a kit piece.
- **Wang-set output mode** — a tile set that removes repetition by construction. Trigger: seed
  variants do not fix repetition.
- **Wave B: runtime layering** — a shared tileable set plus a per-object detail layer on UV1 in
  the renderer, stochastic (hex) tiling and a world-space macro layer. Trigger: the spike's Go
  *and* a measured bake-time or memory cost of per-object baking that matters.
- **Mesh-aware (Painter-like) wave** — edge wear, curvature and AO-driven masks on a specific
  mesh. Trigger: tileable sets proven, and content that needs per-mesh wear.
- **Reference comparison in the feedback loop** — scoring a render against a reference image.
  Trigger: the log shows the agent iterating blind on a look.

## Out of scope

Node-graph UI, an editor texture surface, wire commands, an expression language, voxel texturing,
and any runtime procedural generation in a game binary.

## Risks

- **The claim fails.** Mitigated by the spike and its park rule; the crate is isolated.
- **Op-library churn re-textures committed art.** Mitigated by decision 9: a drift diff is a
  reviewed change.
- **Cross-arch float drift.** Mitigated by decision 6 and a cross-arch check on the pinned machines.
- **Visible tiling.** Decision 17 measures it; Later waves answer it.

## Status

Wave 0 (the spike) — **Go**, 2026-10-24:

- **Core crate.** `ludion-texgen` parses a `kind: texture` recipe and evaluates its step DAG on the CPU into the PBR map set as PNG bytes; thirteen ops (noise, gradient, constant, blend, levels, curve, clamp, remap, colorize, grayscale, warp, blur, normal), diagnostics `L1283`–`L1285`, pinned output hashes at two sizes.
- **Hard generators.** `tile_sampler`, `flood_fill`, `distance`, `ambient_occlusion`, `curvature` and the `image` op; `normal_from_height` uses a Sobel filter.
- **`std:` library.** `op: input` and `inputs:` bindings let a sub-recipe receive images; five embedded macros (`edge_wear`, `cavity_grime`, `cobbles`, `planks`, `rust_spots`), `std:` references resolved from the binary.
- **`ludion texture` verb.** `build`, `check` (the drift gate, `L1286`) and `vendor`; nine validators (seven PBR, two repetition) with a rules TOML (`L1287`–`L1289`); `kind: texture` is checked by the verb; `examples/textures/tiles.texture.yaml` is the worked example. Docs: `ludion docs texture-recipes`, `ludion docs texture-ops`, `ludion devdocs ludion-texgen`.
- **Feedback loop.** `build --preview` writes the map sheet, step thumbnails, 2×2 tiling views and a Ludion-rendered preview (a generated scene with sphere, rounded cube and panel) into an ignored `.ludion/texture/<stem>/`; the `bench40` recipe measures speed: warm-run budget met on the M5, cold shader compile excluded, the M4 measurement owed.
- **Reference materials.** `examples/textures/`: cobble, oak planks, painted iron and the hand-painted cobble restyle, each under the drift gate; the spike log below records the iterations and the missing ops.
- **Kit piece.** The reference game's crate rebuilt from a generated set beside its node-material twin; details private.

Wave 1 — in progress.

- **Layout ops.** `tile_sampler` gains `offset_jitter`, `gap` and per-instance pattern scale and offset jitters; `std:planks` is rebuilt on them (uniform joints in tile units, `bevel`, `stagger_jitter`, `gap: 0` is one board) and `std:cobbles` gains an opt-in `round` profile.

## Spike log (W0)

Four reference materials, authored only through the feedback loop (`build --preview` at 512²: the map sheet, step thumbnails, 2×2 tiling views, the rendered preview and the validators), in `examples/textures/`. No op or macro was added; every gap was worked around from the existing library.

| material | iterations | stop | build @512 (M5, warm) |
| --- | --- | --- | --- |
| `cobble` | 10, plus a four-seed scan | judged competent after a realism round: per-stone cool/warm hue and value, multi-scale albedo breakup, dark soil in the joints with grime creeping up the stone bases, smooth worn tops over rough sides, rounded profiles | ~265 ms (43 steps) |
| `oak_planks` | 8 | judged competent after a realism round: per-board tint, ring spacing and grain offset, knots that bend the grain, sparse dark streaks, softer gaps, darkened board edges, roughness varying along the grain; `repetition_peak` warns (see below) | ~260 ms (60 steps) |
| `painted_iron` | 8 | judged competent: riveted panels, paint chipped from the edges, rust in the chips, bare metal metallic 1, paint 0 | ~215 ms (44 steps) |
| `cobble_painted` | 6 | the same `std:cobbles` layout reads as hand-painted: flat value bands, painted rim highlights, an ink outline, soft colour drift, a low-detail normal | ~150 ms (27 steps) |

The hardest things:

- **`cobble`** — the stones were faceted polygons with flat plateaus. A larger `bevel` plus a shared `warp` of the height, mask and id (the same `by` on all three so they stay aligned) rounded them; a per-stone `flood_fill` gradient added the tilt that makes them read as separate stones. A joint exactly on the wrap seam fails `seam_base_color`, and only the recipe seed moves it.
- **`oak_planks`** — `std:planks`' pyramid profile shades as diamonds on boards much wider than tall, and its rows repeat every two rows, which scored a 0.83 repetition peak. The recipe builds its own boards (`tile_sampler` box), shifts each row by a per-row random through `warp`, and offsets the grain per board by warping with `board_id`.
- **`painted_iron`** — the chip mask. Cellular blobs read as polka dots; a thresholded fbm masked by an edge zone and a field zone reads as chipped paint. Rust and bare metal must live only inside the chips, and `std:rust_spots` `coverage` has to be low or it fills the plate.
- **`cobble_painted`** — `overlay` brightens to white against a 0..1 band image, so the bands are remapped around 0.5 first; `edge_wear` is too broad on a soft height, so the rim highlight is a `curve` on the blurred height instead.

Missing ops and features:

| op / feature | needed by | workaround | cost | added |
| --- | --- | --- | --- | --- |
| Anisotropic (stretched) noise, for wood fibres | `oak_planks` | a high-repeat `gradient` warped by a mid-scale noise | M | no |
| Per-row random offset in `tile_sampler` (staggered boards that do not repeat) | `oak_planks` | a per-row random image warped along `u` | S | no |
| Uniform gap width on a non-square grid (`tile_sampler` `scale` is relative to the cell) | `oak_planks` | accept a wider end gap, soften it with `blur` | S | no |
| Rounded layout from `std:cobbles` (a profile with no facets) | `cobble`, `cobble_painted` | a larger `bevel` and a shared `warp` | S | no |
| A thin rim or outline from a height (a band, not `edge_wear`'s broad crests) | `cobble_painted` | a `curve` peaking over the band | S | no |
| Posterize / quantize | `cobble_painted` | a stepped `curve` | S | no |
| Seam-safe seed choice, or a validator-guided seed search | `cobble`, `cobble_painted`, `painted_iron` | scan the recipe seed by hand | S | no |
| Directional (anisotropic) blur or smear, for rust streaking below chips and board-end darkening | `painted_iron`, `oak_planks` | not done for the streaks; the end darkening uses the isotropic `distance` and also darkens the long edges | M | no |
| Per-instance scale of a pattern (ring spacing per board) | `oak_planks` | two ring sets mixed by a per-board mask | S | no |
| Layer helper (colour, roughness and metallic from one mask in one step) | all four | repeated `blend` with `mask`, 30–50 steps per material | M | no |

`repetition_peak` is a false positive for directional patterns: a long-grain board floor is invariant along the grain, so its autocorrelation has a strong off-centre peak at the row pitch (0.80 on `oak_planks`). It warns and does not fail; a per-recipe bound in a rules file is the fix if the warning matters.

Derived param values (arithmetic) were not needed: no recipe wanted a value computed from another.
