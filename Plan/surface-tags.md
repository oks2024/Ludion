# Plan: Surface tags — what a hit is standing on

> Status: **W1–W2 mechanized** (declared surfaces, `SurfaceTag`, `SurfaceOverlay`, `surface` on every hit that names a collider); W3a mechanized (per-part); W3b mechanized (triangle and cell tags); W3c mechanized (glTF import); W4 mechanized. Origin: Neon Shroud request 0009 (footstep noise by floor material). Parent plans: `Plan/physics.md`, `Plan/physics-collision-layers.md` (the side-table pattern this mirrors), `Plan/character-controller.md` (its non-goal "Per-triangle surface tags" is lifted as tags only).

## Trigger

The first consumer is the external stealth game Neon Shroud (request 0009): the footstep noise a guard hears depends on the floor under the player — concrete, a metal grate, a puddle. The motor already reports `ground.entity`; the game needed the engine to answer "which surface" so noise tables stay game data.

## Decisions

1. **`SurfaceTag` is a side component, not a `Collider` field.** `Collider` has ~128 full struct literals across crates and games; a field breaks all of them. A tag is query-only data the solver never reads — the `QueryLayers` class: an entity-sorted side table refreshed by the write, resolved against the settings, an undeclared name degrades with one rejection and keeps its body. Live edits are free (no rebuild). Per-part tags extend `SurfaceTag` (a `parts` list of `{ part, surface }`; an integer `part` indexes the entity's `compound` parts, a string names a `kind: assembly` part), not `CompoundPart`.
2. **Per-scene `physics.surfaces`.** A list of names; the order is the `SurfaceId`; at most 256. Optional `default_surface` is reported for any untagged collider hit (motor capsules included).
3. **Resolution order:** `SurfaceOverlay` containing the hit point → mesh triangle / heightfield cell → `SurfaceTag.parts` part → entity `SurfaceTag` → `default_surface` → `None`.
4. **An undeclared tag at runtime** is one `L1690` rejection; its hits report the default; the body is kept. `check-scene` reports it statically with the nearest declared name (`L1690`), an empty or repeated name or more than 256 is `L1691`, a tag with no claimed collider or motor is `L1692`.
5. **The engine stores no scalar per tag.** Noise and sound tables are game data.
6. **`QueryHit`, `PointHit`, `GroundHit` and `SurfaceHit` gain the public `surface` field**, not `#[non_exhaustive]` — ratified 2026-11-18 (no game constructs these literals); an additive change recorded in `Plan/api-freeze-engine.md`.
7. **The snapshot schema omits the new `scene_physics` fields — accepted 2026-11-19, scheduled (R14 re-record round).** `surfaces`/`default_surface` on `ScenePhysicsDoc` carry `#[schemars(skip)]` (serde default and skip-when-empty kept), because a schema change moves `replay_content_hash` and fails every committed `.lrp` (L3010). Precedent: the snapshot's `unknown` field, `Plan/game-time-scale.md` decision 9. The schema names them again at the next corpus re-record. Guard: `the_snapshot_schema_omits_the_surface_fields`.
8. **`SurfaceOverlay { surface, priority }` needs a sensor volume.** It sits on an entity with a solver-claimed `Collider` with `sensor: true` (`L1693` otherwise); `priority` is an `i32`, default 0. Any hit whose point lies inside one or more overlays reports the highest priority's surface, ties to the lowest `EntityId`. Read at query time from the last completed step's pose (a moved kinematic overlay is seen from the next step). An undeclared overlay name is one `L1690` rejection and the overlay is inert. Tags only: an overlay never reaches the solver.
9. **`surface_under(point, reach, filter)`** answers "what is under this point": an overlay containing `point`, else a downward ray of `reach` through `filter`, resolved by `surface_at(entity, point)` at the hit point; `Ok(None)` on no hit. `surface_at(entity, point)` is the shared resolver (overlay, then the entity's tag) the query sites use. `surface_under` returns `Result<Option<SurfaceId>, PhysicsError>` (`Err(QueryInput)` on a non-finite point or a negative/non-finite reach), a deliberate divergence from request 0009's `Option<SurfaceId>` so every query reports bad input the same way.
10. **Part keys (W3a).** An integer key indexes the entity's own `compound` `Collider` parts; a string key names a part of the entity's `kind: assembly` mesh. While an assembly moves as one body the string keys are inert; `switch_to_ragdoll` writes each spawned part a `SurfaceTag` with its named entry's surface, else the root's `surface`, and the root keeps its tag. An unmatched name key falls back to the root surface with one `L1695` warning at the switch (a typo must not cancel a death ragdoll). `L1694`: an empty or repeated key, an integer key not on a `compound` collider or past its last part, a string key on a non-assembly entity. The tag carries no scalar and no 2D form.
11. **Part resolution (W3a).** The part whose shape is nearest the hit point (solid `distance_to_point`), lowest index on ties, read from the last completed step's pose; the same for every query and the motor (they all resolve through `surface_at`). Entities with no part entries return before touching the solver, so an untagged scene pays nothing. `parts` is skipped when empty: every existing scene, trace, replay and golden is byte-identical.
12. **Mesh triangle tags (W3b).** A mesh document gains optional `surfaces` (local names, at most 256) and `triangle_surfaces` (run-length `[count, local index]` in triangle order), both or neither, counts summing to the triangle count, else `L1696`. The names are local and matched to `physics.surfaces` at load; a name the scene does not declare is an `L1697` warning (statically in `check-scene`, once at runtime) and those triangles fall through to part, entity and default.
13. **Face resolution (W3b).** The triangle (or cell) nearest the hit point in the collider's local frame; candidates within `1e-4` m of the best distance tie and the lowest triangle index wins. No ray feature ids: ray, shape cast, closest points and the motor all pass a point to `surface_at`, so they agree by construction. Heightfield cells use parry's `closest_cell_at_point` (`(i, j)` is row along `z`, column along `x`, cell `i * (cols-1) + j`, matching the authored row-major heights); observed seam rule: a point exactly on an edge between two cells takes the higher-index cell. Cells live on `SurfaceTag.cells` (`{ surfaces, runs }`, `(rows-1)*(cols-1)` cells), not on the shape: a `Shape::Heightfield` field would break 21 literals (decision 1).
14. **Restore (W3b).** The tagged-mesh table is refilled from the loaded documents, so a restore refills it at the world rebuild (`sync_mesh_surfaces`, called after `install_collider_meshes`); a query before the first write answers as the original run did.
15. **The tags travel beside `MeshDocument` (W3b).** `MeshSurfaces` via `check_mesh_surfaces` / `emit_mesh_with_surfaces`, because a new public field breaks an external game, which builds `MeshDocument` struct literals in two test helpers. `emit_mesh` omits the keys, so a tool that reads a mesh document and writes one back must use the pair. Audit: `ludion mesh apply` (`ludion-mesh-edit` derive) carries the tags (its triangles are unchanged); `ludion-import`, `ludion-gen` accept and `texture_preview` build documents in memory and rewrite none; `ludion-sculpt` reads geometry only.
16. **glTF import (W3c).** The key is a material's `extras.ludion_surface` only, never a material name: a renamed material must never move a committed derived tree, and Blender writes custom properties to extras. One glTF primitive is one material is one mesh document, so an imported document carries one name and one run over all its triangles; a two-material floor imports as two documents. A value that is not a non-empty string is `L1201` naming the material; a document with zero triangles carries no keys (a zero-count run is `L1696`). **LOD:** every level carries its base's tag. Generated levels copy the base's name with one run over the level's own triangle count; an authored level whose `ludion_surface` differs from its base's (including one tagged, one not) is `L1396` naming `surfaces`, as an `alpha_mode` mismatch is. Why: a level is the same surface seen from farther away, and a `Collider` may name a level document as its cheap collision mesh, so a level must never answer a different surface. With no `extras.ludion_surface` anywhere, every re-import is byte-identical.

17. **Contact surfaces are a method (W4).** `PhysicsWorld::contact_surfaces(&event) -> [Option<SurfaceId>; 2]`, `[a's, b's]`, not `ContactEvent.surface_a/b`: `ContactEvent` sits inside the positional physics snapshot blob (`ContactWindow`, `SnapshotRef`/`SnapshotOwned`), a field change needs a `PHYSICS_BLOB_VERSION` bump, and that version is inside `replay_content_hash`, so a bump fails every committed `.lrp` with `L3010`. A `Started` event resolves each side with `surface_at` at the event's point; a `Stopped` event has no point and answers `[None, None]`. It is a pure read of the last completed step, so a restore answers identically with no new state. An overlay containing the point answers for both sides (a crate dropped in a puddle splashes).
18. **Map-kit `surface` (W4).** `collider: { box: [x, y, z], surface: name }` in a `kind: map-kit` primitive emits `SurfaceTag: { surface: name }` on the entity carrying the `Collider` (the `-collider` sibling, or the one entity of a collider-only primitive). Box only: `aabb`/`circle` live in the 2D index, which reports no surfaces, so `surface` there is `L1022` at `<collider>/surface`, as is an empty or non-string name. A kit has no scene, so the name is checked by `check-scene` on the generated scene (`L1690`), not by map-check.
19. **`surfaces` debug draw (W4).** Every collider outline tinted by the surface a hit there reports, listed only when the scene declares surfaces. The rule is `surface_at`: a tagged mesh or heightfield draws each triangle inset 10% toward its centroid in the surface of that centroid (the colliders view drops coplanar internal edges, so a flat two-tag floor would show only its outline; the inset keeps regions apart, and an overlay tints the floor under it); an overlay draws its own outline; other sensors are skipped; every other collider draws per segment, by the surface of its midpoint. Palette by declared id mod 8, untagged grey `[0.35, 0.35, 0.35]`. Debug lines carry no text, so the legend is the table in `docs/debug-draw.md`.
20. **Motor trace (W4).** `GroundRecord` and `SurfaceRecord` gain `surface` (the declared name), omitted when none, so every untagged trace is byte-identical.

## Waves

- **W1 — this wave.** `physics.surfaces`/`default_surface` (parse, emit, validate, snapshot), `SurfaceTag`, `SurfaceTable`/`SurfaceId`, `PhysicsWorld::{surface_id, surface_name, surface_of, sync_surface_tags}`, `surface` on the four hit structs, `check-scene` L1690/L1692, docs (`collision`, `motor`, `physics`).
- **W2 — overlays (mechanized).** `SurfaceOverlay { surface, priority }` and `PhysicsWorld::surface_under(point, reach, filter)` (puddles: the overlay wins at the hit point, ties lowest entity).
- **W3a — per-part (mechanized).** `SurfaceTag.parts` (`PartSurface`, `SurfacePart`), compound index keys resolved by nearest part, assembly name keys inherited by `switch_to_ragdoll`, `L1694`/`L1695`.
- **W3b — finer than the collider (mechanized).** Mesh `surfaces`/`triangle_surfaces` run-length (`MeshSurfaces`), heightfield `SurfaceTag.cells`, nearest-face resolution for every query and the motor, `L1696`/`L1697`.
- **W3c — glTF import of tags (mechanized).** `ludion import` writes `surfaces: [x]` + `triangle_surfaces: [[n, 0]]` only when a primitive's material carries `extras.ludion_surface` (never from material names, so every existing re-import stays byte-identical).
- **W4 — surround (mechanized).** `PhysicsWorld::{contact_surfaces, surface_names, surface_wireframe}`, the kit `surface` key, the `surfaces` debug-draw category, the motor-trace `surface` name, the `surface-tags` gallery scene and golden.

## Out of scope

check-scene resolving assembly part-name keys against the loaded assembly (trigger: an `L1695` seen in play); limb hitboxes on a live assembly (the pose is visual-only); a tag in the `kind: assembly` document itself; the 2D tier (`RayHit`, `move_and_slide`) — no trigger; nav costs by surface; voxel palettes; a BVH over overlays (trigger: a profile showing overlay resolution above 0.05 ms/tick; today a linear scan with an AABB reject).
