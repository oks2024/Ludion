# The frame's passes

**Scope:** The per-frame walk over the passes `build_frame_graph` scheduled, and the composite imaging chain. The graph itself — pass order, the conditional chains, which extent sizes which target — is `ludion devdocs ludion-renderer`.

`Renderer::render` schedules the graph, then `prepare_frame(scene)` uploads every buffer the recorder will bind — including a **zeroed** sun uniform when the scene has none, so a sunless frame's group-2 bind group is well-formed but inert — and returns a `FrameRecorder` that `Gpu::execute` calls back per pass. What is not recoverable from `record_*` in one read:

- **scene** is the opaque pass: it draws meshes only, into three colour targets — `scene` (HDR), plus the normal + roughness and F0 + specular-occlusion targets `reflections` reads — and `scene_depth`. It adds no indirect specular. **reflections** is a fullscreen pass that adds the sky's specular IBL into `scene` (`ludion devdocs renderer-reflections`). **transparents** then draws, over that, the sky, ground markers, sprites, particles and text, in that order. All three write `scene`, so declaration order sequences them. The sky is a far-depth fullscreen triangle inside the `transparents` pass (`LessEqual`), so it fills only the pixels no opaque mesh wrote and sprites blend over it. Ground markers are alpha-blended analytic discs/capsules, depth-tested `Less` and never depth-written, drawn *before* the sprites so a telegraph reads under the character standing on it — a sprite writes no depth, so only the draw order can put it there. Particles are unlit, premultiplied, camera-facing analytic discs, depth-tested `LessEqual` and never depth-written, drawn back-to-front after the sprites and before text; additive vs. alpha blend is a per-instance flag on the same draw rather than a second pipeline. Like the sky and the markers, particles add no pass: an empty `RenderScene.particles` records no draw, so a scene that authors none is byte-identical to the pre-particle pipeline. Sprites, markers, particles and text neither cast into the shadow map nor sample it. A scene with a `DropShadow` adds two passes between `reflections` and `transparents`: **drop_shadow_occlusion** (a depth-only atlas of straight-down tiles, one per caster, the caster's own meshes excluded) and **projector** (one box volume per instance that rebuilds the world position from `scene_depth`, multiply-blended into `scene`); a scene without one records neither. A scene with a `Decal` adds **decals_lit** before `reflections` (lit alpha and coat decals, shaded with the mesh terms; it blends the painted normal, roughness and F0 into the surface targets and writes the `lit_normal` transient that `reflections` reads only then) and **decal_receivers** (a conditional `R32Float` id redraw when some decal excludes a mesh); multiply and add decals draw in `projector`, before the drop shadows (`ludion docs decals`).
- **shadow** is scheduled only when the scene has a sun and the `shadows` effect is on. It draws the anchored box into the `shadow_map` transient, or, with cascades, an atlas of `shadow_map_size` tiles (1×1, 2×1 or 2×2): one viewport and light matrix per tile, each tile drawing only the casters its own CPU cull keeps, through `draw_casters` shared with `local_shadow` (`sun_cascade.rs`: the pure fit, the atlas grid, `sun_cascade_casters`). The pass keeps its name, so `[passes]` budgets hold.
- **local_shadow** is scheduled only when the frame grants at least one shadowed light (`local_shadow::plan`): it renders every granted view into one transient depth atlas, each view through the existing shadow pipeline (skinning included), drawing only the instances the CPU `cull` keeps for that view (skinned ones always). A frame with no grant keeps its previous graph exactly, and the `shadows` quality effect masks it with the sun's `shadow`. Probe captures are never locally shadowed. **local_shadow_debug** replaces `composite` for `--debug-view local_shadow_atlas` (`ludion devdocs ludion-cli`).
- **Skinning** happens in the vertex stage, shared by shadow, prepass and scene: each mesh vertex blends up to four joints from `@group(0) @binding(1) bone_palette` (`array<mat4x4<f32>>`), keyed by the instance's `bone_offset` (carried in the spare `fade.z` lane). `bone_offset == 0` takes the unskinned arithmetic *textually*, not just numerically at identity — which is why no unskinned golden can move when skinning lands. A skinned normal takes the sign-corrected, normalized cofactor of the blended matrix (`skin_normal`, so a non-uniform joint scale keeps it perpendicular to the surface); the tangent takes the matrix itself. The renderer prepends its own identity entry 0 to the buffer, so a skinned instance's own palette starts at offset 1; extract fills each instance's slice from `MeshData.skin_joints`: a joint a `SkinBone` part names is posed from that part's live world transform every frame; every other joint keeps its rest pose relative to its parent.
- **prepass** owns its own depth attachment instead of handing one to the scene pass, so the scene pass's `Less` test and clear are untouched (an AO frame rasterizes its geometry twice). `ssao_blur` then cancels the estimator's per-pixel rotation; the scene pass multiplies the result into the diffuse ambient + IBL term plus the `ssao_direct` fraction of the direct lobes, and writes it into `scene_specular.a`, where `reflections` applies it to the sky's specular.
- **bloom_down_1 and only it** Karis-averages its boxes, so a lone hot pixel cannot ride the 13-tap chain down as a firefly. Each upsample adds a tent over the coarser accumulation to that level's own downsample, so `bloom_up_0` — always `composite`'s second input — is the sum of all six levels.
- Both blurs are `box_blur.wgsl`, whose 4×4 width is the `BAYER4` tile's **period**: it cancels either estimator's dither exactly, so it is not a quality dial.
- **dof_coc** exists so each of the gather's 32 taps is one fetch instead of a colour, a depth and a matrix multiply; it area-averages the colour once instead of per tap and takes the CoC from the *nearest* source texel, so a silhouette does not thin.
- **composite** is the whole per-pixel imaging chain in one pass, in a pinned order that is part of `PostProcess`'s contract, not an implementation detail: chromatic aberration (at the fetch), the depth-of-field blend, `scene + bloom × bloom_strength + halation`, the medium's two terms, exposure, the `tonemap` operator, the colour grade, the vignette, grain, the output dither. The split is scene-referred against display-referred: the medium happens to the light on its way to the lens, so it blends in linear HDR before the operator, while the grade and vignette darken the *finished image* and grain is the emulsion recording it. The dither is strictly last because it hides the output quantization; with SMAA on, composite zeroes grain and dither and `smaa_blend` applies them instead. Every step sits behind a uniform branch, so a neutral step is skipped rather than computed; the two shipped defaults deliberately *not* neutral are exposure `1.3` and the dither, because both are the imaging chain rather than an authored effect. An absent optional input (the shaft or DoF term) binds a 1×1 stand-in in a fixed slot order rather than selecting a second pipeline.
- The dither is applied in the **encoded** domain: the target is `Rgba8UnormSrgb` and the hardware encodes on store, so a sub-LSB offset added to the linear output would be worth the wrong number of output steps at every luminance. `dither_output` encodes, offsets by `(BAYER4 ± half a step) / 255`, decodes, and lets the hardware re-encode — no format change, and dither-off stays byte-identical.
- **smaa_edges → smaa_weights → smaa_blend** are scheduled only with `AntiAliasing::Smaa`, after `composite` and before `resolve`: composite writes the transient `aa_input` instead of its usual target; `smaa_edges` runs luma detection (fixed HIGH constants) into an edge texture, `smaa_weights` reads it plus the area and search LUT textures, and `smaa_blend` blends `aa_input` by the weights, then applies grain and dither (the Rgba16Float intermediate keeps the quantization honest). Debug views schedule none of them.
- **resolve** always sits after `composite` and before `overlay`, so screen-space UI is rasterized once at output resolution and never passes through the downsample. It is `textureLoad`-based, so a fractional ratio carries no half-texel error.
- **overlay** blits `ldr` loaded, not cleared (the blit covers every pixel), then draws the UI batches in the scene's pinned order. It reads `ldr` and never the HDR scene target, so bloom cannot reach it.

`Renderer::dump_timings_json` reuses the graph's single timings machinery; the scene pass hand-attaches `pass.timestamp_writes()` because it builds its own render-pass descriptor.
