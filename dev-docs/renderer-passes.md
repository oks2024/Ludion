# The frame's passes

**Scope:** The per-frame walk over the passes `build_frame_graph` scheduled, and the composite imaging chain. The graph itself — pass order, the conditional chains, which extent sizes which target — is `ludion devdocs ludion-renderer`.

`Renderer::render` schedules the graph, then `prepare_frame(scene)` uploads every buffer the recorder will bind — including a **zeroed** sun uniform when the scene has none, so a sunless frame's group-2 bind group is well-formed but inert — and returns a `FrameRecorder` that `Gpu::execute` calls back per pass. What is not recoverable from `record_*` in one read:

- **scene** is the opaque pass: it draws meshes only, into three colour targets — `scene` (HDR), plus the normal + roughness and F0 + specular-occlusion targets `reflections` reads — and `scene_depth`. It adds no indirect specular. **reflections** is a fullscreen pass that adds the sky's specular IBL into `scene` (`ludion devdocs renderer-reflections`). **transparents** then draws, over that, the sky, ground markers, sprites, particles and text, in that order. All three write `scene`, so declaration order sequences them. The sky is a far-depth fullscreen triangle inside the `transparents` pass (`LessEqual`), so it fills only the pixels no opaque mesh wrote and sprites blend over it. Ground markers are alpha-blended analytic discs/capsules, depth-tested `Less` and never depth-written, drawn *before* the sprites so a telegraph reads under the character standing on it — a sprite writes no depth, so only the draw order can put it there. Particles are premultiplied, camera-facing analytic discs, unlit by default and, per emitter opt-in (`lit`), shaded once per centre in the vertex stage by the sprite's `shade_two_sided` (`snippets/billboard_light.wgsl`; the lights group is bound for the draw), depth-tested `LessEqual` and never depth-written, drawn back-to-front after the sprites and before text; additive vs. alpha blend is a per-instance flag on the same draw rather than a second pipeline. Like the sky and the markers, particles add no pass: an empty `RenderScene.particles` records no draw, so a scene that authors none is byte-identical to the pre-particle pipeline. A blended mesh (`Mesh.blend`, `RenderScene::blended`, never in `meshes`) draws in `transparents` right after the ground markers and before the sprites: one draw per instance in `render/blended.rs` `blend_order` order (groups far to near by the view distance to the group's world-AABB centre), through the mesh shader's lazily built `BlendTwins` (`fs_blend`, `BLENDED` true so the Bayer discard is off and alpha is `coverage · fade`), depth-tested `Less`, never depth-written, lit by the scene pass's shadow map, dynamic GI volume and local shadow atlas (the graph declares those reads on `transparents` and `transparent_depth` only when `PostChain::blended`; ambient occlusion is never read). A lit blended mesh also gives itself the indirect specular `reflections` gives an opaque mesh, inline in `fs_blend`/`fs_blend_layer` (`blend_shade`, `blend_fill` in `mesh.wgsl`, never SSR): it binds the sky specular cube, the probe cube arrays, the probe list and mask and the relight table at group 3 slots 12–17 (`render/blended.rs` `BlendReflections`; every other mesh draw binds fallbacks), and the two passes read `probe_live` after the lighting tail and before the rain map when the scene has probes. `record_blended` hands `shading_groups` only the lighting tail (`inputs[..n]`), so the trailing reads never land in a shadow slot. `BLEND_UNLIT` (`Mesh.lit: false`) is a second, lazily built set of twins that skips light, wrap and the fill. A `blend_depth: nearest` group (`BlendedMesh::nearest`; one `BlendedSegment` per group in `BlendedDraw`) cannot draw inside the pass, because its front surface needs a writable depth the sprites, particles and the composite's fog must not see: `record_blended` ends the pass, copies `scene_depth` into a renderer-owned scratch depth (`Renderer::scratch_depth`, cached by extent, allocated on the first `nearest` frame; the graph declares `CopySrc` on `scene_depth` only with `PostChain::blend_nearest`), draws the group depth-only into it (`BlendTwins::prepass`: the colour draws' vertex stage and layout, no fragment, `Less`, write on), then draws its colour read-only against it through the `LessEqual` twins, and returns a reopened pass (`MainPass::open`, loading colour and depth) for what follows. One copy per group, so a nearer group is not clipped by an earlier one's front surface. The graph pass keeps one timestamp pair: the begin index rides the first main pass, the end the last, and the passes between carry none. `transparent_depth` breaks the same way into its layer. No depth bias: both pipelines share `vs_main`, and an alpha-1 `nearest` figure matches its opaque twin on the RTX 3090 (the M4 is unmeasured). The mesh fragment stage samples 16 textures plus the blended meshes' four, so `engine_limits` raises `max_sampled_textures_per_shader_stage` to 20. Sprites, markers, particles and text neither cast into the shadow map nor sample it. A scene with a `DropShadow` adds two passes between `reflections` and `transparents`: **drop_shadow_occlusion** (a depth-only atlas of straight-down tiles, one per caster, the caster's own meshes excluded) and **projector** (one box volume per instance that rebuilds the world position from `scene_depth`, multiply-blended into `scene`); a scene without one records neither. A scene with a `Decal` adds **decals_lit** before `reflections` (lit alpha and coat decals, shaded with the mesh terms; it blends the painted normal, roughness and F0 into the surface targets and writes the `lit_normal` transient that `reflections` reads only then) and **decal_receivers** (a conditional `R32Float` id redraw when some decal excludes a mesh); multiply and add decals draw in `projector`, before the drop shadows (`ludion docs decals`).
- **shadow** is scheduled only when the scene has a sun and the `shadows` effect is on. It draws the anchored box into the `shadow_map` transient, or, with cascades, an atlas of `shadow_map_size` tiles (1×1, 2×1 or 2×2): one viewport and light matrix per tile, each tile drawing what the GPU cull kept for its view, through `draw_casters` shared with `local_shadow` (`sun_cascade.rs`: the pure fit, the atlas grid, `sun_cascade_casters`, the CPU oracle for the tile counts). The pass keeps its name, so `[passes]` budgets hold.
- **local_shadow** is scheduled only when the frame grants at least one shadowed light (`local_shadow::plan`): it renders every granted view into one transient depth atlas, each view through the existing shadow pipeline (skinning included), drawing what the GPU cull kept for that view. A frame with no grant keeps its previous graph exactly, and the `shadows` quality effect masks it with the sun's `shadow`. Probe captures are never locally shadowed. **local_shadow_debug** replaces `composite` for `--debug-view local_shadow_atlas` (`ludion devdocs ludion-cli`).
- **Skinning** happens in the vertex stage, shared by shadow, prepass and scene: each mesh vertex blends up to four joints from `@group(0) @binding(1) bone_palette` (`array<mat4x4<f32>>`), keyed by the instance's `bone_offset` (carried in the spare `fade.z` lane). `bone_offset == 0` takes the unskinned arithmetic *textually*, not just numerically at identity — which is why no unskinned golden can move when skinning lands. A skinned normal takes the sign-corrected, normalized cofactor of the blended matrix (`skin_normal`, so a non-uniform joint scale keeps it perpendicular to the surface); the tangent takes the matrix itself. The renderer prepends its own identity entry 0 to the buffer, so a skinned instance's own palette starts at offset 1; extract fills each instance's slice from `MeshData.skin_joints`: a joint a `SkinBone` part names is posed from that part's live world transform every frame; every other joint keeps its rest pose relative to its parent.
- **prepass** owns its own depth attachment instead of handing one to the scene pass, so the scene pass's `Less` test and clear are untouched (an AO frame rasterizes its geometry twice). `ssao_blur` then cancels the estimator's per-pixel rotation; the scene pass multiplies the result into the diffuse ambient + IBL term plus the `ssao_direct` fraction of the direct lobes, and writes it into `scene_specular.a`, where `reflections` applies it to the sky's specular.
- **bloom_down_1 and only it** Karis-averages its boxes, so a lone hot pixel cannot ride the 13-tap chain down as a firefly. Each upsample adds a tent over the coarser accumulation to that level's own downsample, so `bloom_up_0` — always `composite`'s second input — is the sum of all six levels.
- Both blurs are `box_blur.wgsl`, whose 4×4 width is the `BAYER4` tile's **period**: it cancels either estimator's dither exactly, so it is not a quality dial.
- **dof_coc** exists so each of the gather's 32 taps is one fetch instead of a colour, a depth and a matrix multiply; it area-averages the colour once instead of per tap and takes the CoC from the *nearest* source texel, so a silhouette does not thin.
- **medium_scatter / medium_scatter_blur** are scheduled when `PostChain::medium_scatter` holds (selected scattering lights or a nonzero-strength `GiVolume`, with a medium; no sun needed). The march reads depth, the transparent layer, the local-shadow atlas and the injected GI volume at group 0, and the baked GI volumes at group 1; the blur is `box_blur`'s 4×4 over its four channels, and `composite` adds the result at binding 6 right after the shafts (`ludion devdocs renderer-medium`).
- **transparent_depth** runs after `transparents`, only when a sprite, particle, world text or blended mesh is drawn and fog or DoF is on, with no debug view (`PostChain::transparent_depth_scheduled`, shared by graph and recorder). It redraws those three, preceded by the blended meshes (`fs_blend_layer`, the same shading reduced to the weight `a`, an additive one `a · min(1, max(rgb·a))`), in the same order and depth compare into an `Rg16Float` target of `(t·w, w)` (`Rgba16Float` with the weighted medium scale in B when an exempt sprite or particle is drawn): `t` the distance along the view ray (depth along the view under ortho), `w` the blend weight; an additive texel claims `coverage · min(1, max(rgb))`. Three readers: `composite.wgsl` fog (`mix(F_background, F(t̄), G)`), `dof_coc.wgsl` (CoC from `t̄`) and `shafts.wgsl` (samples past `t̄` count for `1-G`). The graph holds its read slot last, so an absent pass leaves every other resource list unchanged and composite binds a 1×1 fallback. Sky and ground markers do not draw. Spelling is load-bearing for byte identity on Metal (`Plan/transparent-depth.md`).
- **lens_down_1..5 / lens_up_4..0** are scheduled only when `PostProcess.anamorphic > 0` (`PostChain::anamorphic`): an x-only chain off `bloom_down_1` (four bilinear taps down, a horizontal tent up blended by `anamorphic_length`), `lens_down_1` alone taking the streak's extra threshold. `lens_up_0` is `composite`'s eighth optional input (binding 10); the gains are Rec.709-luma-normalized on the CPU. The `lens` budget group sums the ten.
- **exposure_meter** is a compute pass scheduled only for `exposure_mode: metered` with no debug view (`PostChain::exposure_meter_scheduled`, shared by graph and recorder; the `irradiance` view stays unmetered; the `exposure_meter` view keeps the meter). One workgroup of 256 reads a fixed 128×72 grid of the HDR `scene` and `scene_depth` into workgroup integer atomics (64 log2 bins over `[-16, 8)`, a fixed-point per-bin log2 sum), then one thread trims, averages and writes the 65×1 `Rgba32Float` `exposure` table (texel 64 = correction EV, mean log2, total weight, gain). `composite` reads texel 64 as its tenth optional input (binding 12, `exposure_tex`, unfilterable) and multiplies the gain in right after `exposure`; the CPU applies `exposure_compensation` to `exposure` itself. Integer atomics are order-independent, so a machine's bytes repeat. It reads what bloom reads and is declared after `bloom_threshold`; the `exposure` budget group is this one pass. **`exposure_meter_debug`** (`--debug-view exposure_meter`, `PostChain::exposure_meter_view`, set only when the scene meters) replaces `composite` with the dimmed frame and the histogram over the bottom quarter, reading `scene` and the table (`exposure_meter_debug.wgsl`); it is a debug pass in no budget group, and the `exposure` transient carries `CopySrc` so `Renderer::set_meter_readback` can copy texel 64 into a three-deep ring (`exposure_readback.rs`, the `cull_stats.rs` shape) that `ludion render` prints.
- **composite** is the whole per-pixel imaging chain in one pass, in a pinned order that is part of `PostProcess`'s contract, not an implementation detail: chromatic aberration (at the fetch), the depth-of-field blend, `scene + bloom × bloom_strength + halation + anamorphic`, the medium's two terms, exposure, the `tonemap` operator, the colour grade, the `.cube` LUT (step 7a, indexed by the sRGB-encoded colour; `RenderScene.lut` uploaded once per content hash as a renderer-owned 3D texture at binding 11, so `dump-graph` never changes), the vignette, grain, the output dither. The split is scene-referred against display-referred: the medium happens to the light on its way to the lens, so it blends in linear HDR before the operator, while the grade and vignette darken the *finished image* and grain is the emulsion recording it. The dither is strictly last because it hides the output quantization; the last pass before the overlay owns grain and dither: composite, or `smaa_blend` with SMAA on, or `resolve`/`upscale` under a resample, with composite (and the blend) zeroing both. Every step sits behind a uniform branch, so a neutral step is skipped rather than computed; the two shipped defaults deliberately *not* neutral are exposure `1.3` and the dither, because both are the imaging chain rather than an authored effect. An absent optional input (the shaft or DoF term) binds a 1×1 stand-in in a fixed slot order rather than selecting a second pipeline.
- The dither is applied in the **encoded** domain: the target is `Rgba8UnormSrgb` and the hardware encodes on store, so a sub-LSB offset added to the linear output would be worth the wrong number of output steps at every luminance. `encoded_output` (`snippets/output_encode.wgsl`, shared by every pass that owns it) encodes, offsets by `(BAYER4 ± half a step) / 255`, decodes, and lets the hardware re-encode — no format change, and dither-off stays byte-identical. The offsets are under half an LSB, so the source must hold more than 8 bits: under a resample `ldr` is half-float.
- **smaa_edges → smaa_weights → smaa_blend** are scheduled only with `AntiAliasing::Smaa`, after `composite` and before `resolve`: composite writes the transient `aa_input` instead of its usual target; `smaa_edges` runs luma detection (fixed HIGH constants) into an edge texture, `smaa_weights` reads it plus the area and search LUT textures, and `smaa_blend` blends `aa_input` by the weights, then applies grain and dither (the Rgba16Float intermediate keeps the quantization honest) unless a resample follows, which owns them and takes a half-float `ldr` from the blend's twin pipeline. Debug views schedule none of them.
- **resolve** always sits after `composite` and before `overlay`, so screen-space UI is rasterized once at output resolution and never passes through the downsample. It is `textureLoad`-based, so a fractional ratio carries no half-texel error. As the last pass before the overlay it applies grain and dither at the **output** extent (so the grain cell and the Bayer tile are the same fraction of the frame at every scale), after clamping each texel of the half-float `ldr` to [0, 1] before mixing; `upscale` does the same. Under a debug view `ldr` stays 8-bit (those passes have no half-float twin) and the resample adds nothing.
- **overlay** blits `ldr` loaded, not cleared (the blit covers every pixel), then draws the UI batches in the scene's pinned order. It reads `ldr` and never the HDR scene target, so bloom cannot reach it.
- **screen_fx_0..3** exist one per applied `ScreenEffect` (at most 4), after `overlay`. With effects the overlay writes the whole-frame transient `screen_fx_layer_0` instead of `final` (an overlay now exists for effects alone, with `ldr`), and `screen_fx_k` blits its layer, draws effect `k` over its rect reading that layer (`screen_effect.wgsl`, blend replace), then UI segment `k + 1` (the UI list is split at each effect's `ui_start`), writing the next layer, or `final` for the last. `final` stays `RenderAttachment + CopySrc`, which is why the layers are whole frames, not region copies. No effect declares no layer: every no-effect graph and command stream is unchanged. Pixels outside every rect are the blit's copy of the layer, byte-equal to the no-effect frame.

`Renderer::dump_timings_json` reuses the graph's single timings machinery; the scene pass hand-attaches `pass.timestamp_writes()` because it builds its own render-pass descriptor.
