# ludion-core

**Scope:** The dependency-light foundation crate every sim-side crate builds on: entity identity (`EntityId`), the diagnostic system (`Diagnostic`, `DiagnosticCode`, the `L####` code table), nearest-match typo suggestions, order-stable collections, the seeded RNG, deterministic math, deterministic data parallelism, and fixed-timestep time types. It knows nothing about ECS storage, YAML, wgpu, or the wire protocol — everything depends on it, it depends on nothing engine-side. For the diagnostic code table and how to add a code, see diagnostics; for consumers, see ludion-ecs and ludion-scene.

## Layout

- `crates/ludion-core/src/lib.rs` — crate root; declares the public modules, nothing else.
- `crates/ludion-core/src/ids.rs` — `EntityId { index: u32, generation: u32 }`, the generational handle value type.
- `crates/ludion-core/src/letterbox.rs` — `letterbox()`/`Viewport`, aspect-preserving placement of a fixed-size frame in a surface; shared by `ludion-window`'s presenter/cursor mapping and `ludion-render-graph`'s present target.
- `crates/ludion-core/src/diagnostics.rs` — `DiagnosticCode` (5-byte inline `L####`) and `Diagnostic` (builder-style, rustc-style `Display`, serde).
- `crates/ludion-core/src/codes.rs` — `mod code` (the `DiagnosticCode` constants), `CodeEntry`, the `CODES` table, `explain()` / `explain_code()`.
- `crates/ludion-core/src/suggest.rs` — `nearest()`, the shared nearest-match helper behind every "nearest match is \`...\`" help text.
- `crates/ludion-core/src/collections.rs` — `StableMap<K, V>` / `StableSet<T>`, BTree-backed newtypes with sorted-order iteration.
- `crates/ludion-core/src/rng.rs` — `DeterministicRng`, hand-rolled PCG32 (PCG-XSH-RR 64/32), two-`u64` serializable state.
- `crates/ludion-core/src/par.rs` — `par_chunks` / `par_map_chunks` / `ordered_reduce` and the worker-count controls (`set_threads`, `with_threads`, `threads`): the engine's only sanctioned sim-path parallelism.
- `crates/ludion-core/src/atomic.rs` — the one temp-then-rename write: `write_atomic`/`copy_atomic` (create parents; a hidden `.<name>.<pid>.<n>.tmp` sibling, removed on failure), `write_all_atomic` (stages every temp, then renames in slice order — not all-or-nothing, a rename failing part-way leaves the earlier targets new). Every writer that replaces a user-visible file uses it (the streaming replay sink is the one exception); a writer that emits several files puts the document or record that names the others last.
- `crates/ludion-core/src/paths.rs` — lexical path confinement (`relative_refusal`, `stem_refusal`, `is_reserved_device`, the `Reserved` refusal for Windows device names), `slash` (the forward-slash spelling every diagnostic uses), `normalize` (the one lexical spelling every asset-cache key takes), `sibling`, and `sibling_refusal` (allows an exact `..`: a sibling path may climb; `../nul.png` is still refused).
- `crates/ludion-core/src/bless.rs` — the one reader of the bless switches (`LUDION_BLESS`, `LUDION_BLESS_ANY_ADAPTER`, `BLESS_SCHEMA`): `bless_requested` / `switch_set`, set = non-empty and not `0`; `scripts/lists-in-step.mjs` rejects a direct read elsewhere.
- `crates/ludion-core/src/require_gpu.rs` — the `LUDION_REQUIRE_GPU=1` contract: `skip_no_adapter` / `is_no_adapter` gate every no-adapter test skip, panicking on a lane that must gate images; `assert_hardware_adapter` counts a software adapter as no adapter on that lane; `LUDION_FORBID_GPU=1` (`assert_gpu_allowed`) is its mirror, panicking on device creation on the hosted no-gpu lane.
- `crates/ludion-core/src/math.rs` — `pub use glam` plus a wrapper for every `f32` transcendental method (and `sqrt`) over pure-Rust `libm`; `math::f64` mirrors them; `math/rotation.rs` and `math/trs.rs` add the Euler XYZ↔quat pair and the `Trs`/`Affine3` composition, pinned by `tests/trs_bits.rs` (`tests/fixtures/trs_bits.txt`).
- `crates/ludion-core/src/audio.rs` — `AudioEvent` (sound, gain, pan, category), `AudioMessage`/`LoopId`/`AudioCategory`: plain-data play requests shared across the sim→playback boundary.
- `crates/ludion-core/src/text.rs` — `single_char(s)`, the single Unicode scalar of a one-character string (glyph legends in `ludion-scene` maps and `ludion-engine` tilemaps validate with it).
- `crates/ludion-core/src/time.rs` — `TickRate` (default 60 Hz), `FrameIndex(pub u64)`, `SimTime { ticks, rate }`.
- `crates/ludion-core/clippy.toml` — the strict denylist, generated by `scripts/clippy-denylist.mjs` (bans `std::HashMap`/`HashSet`, `Instant::now`/`elapsed`, `SystemTime::now`/`elapsed` and the `f32`/`f64` transcendental methods; threads stay allowed here because this crate owns `par`).

## Rules

- `#![forbid(unsafe_code)]`, `#![warn(missing_docs)]` — every public item has a doc comment, usually with a runnable doctest.
- **Types only, no drivers.** The tick loop lives in `ludion-sim`, the id free-list in `ludion-ecs`; never add loop or allocation logic here.
- **No engine dependencies** (serde, glam, libm; serde_json in tests). `EntityId` deliberately does not implement `schemars::JsonSchema` (`ludion-ecs` hand-writes schemas, e.g. `Parent`).
- Determinism rules are mechanically enforced by `clippy.toml`: no std `HashMap`/`HashSet`, no wall clock, transcendentals through `libm` only (each ban names its `math::` replacement).
- Every `DiagnosticCode` constant, from any crate, must be registered in the central `CODES` table here (see diagnostics).
- **`par` is the engine's only parallelism.** Every pure-sim crate's `clippy.toml` bans `std::thread::spawn`/`scope` and `thread::Builder::spawn`/`spawn_scoped`; this crate is the carve-out precisely because it implements the sanctioned primitive. A `par` result must stay independent of worker count — that invariance is the contract, not a nice-to-have.
- `DeterministicRng` constants and algorithm are pinned — validated against O'Neill's published reference vector (seed 42, stream 54) plus golden sequences. Never change the algorithm or seeding procedure without re-blessing every world hash.

## How it works

**ids** — `EntityId` ordering is index-then-generation (the deterministic entity ordering the sim relies on); `Display` renders `e42v3`. Generation bumping and the free-list belong to `ludion-ecs`.

**diagnostics** — `DiagnosticCode::new("L0001")` validates the `L####` shape at compile time; `DiagnosticCode::parse` is the runtime `Option` form. `Diagnostic` has `with_*` builders; `path` is a JSON Pointer into the offending document, and `severity` (`Severity::Error` | `Severity::Warning`) defaults from the code's row in `codes`. `Display` renders rustc-style, leading with the severity word (`error[L0001]: msg` / `warning[L1028]: msg`, then `  --> /path` / `  help: ...`); serde skips empty optionals — severity included, when it is `Error` — so the wire shape stays minimal.

**codes** — one const table, `CODES: &[CodeEntry]`, where `CodeEntry { code, severity, title, explanation }`. All crates' codes are registered here (centralized, grep-able — no `inventory`/`linkme`), and the row is the source of truth for whether a code is fatal. `explain("L0001")` and `severity(code)` are linear lookups. Add-a-code recipe: `ludion devdocs diagnostics`.

**suggest** — public `nearest(target, candidates)`: case-insensitive optimal-string-alignment (restricted Damerau-Levenshtein) edit distance with a plausibility budget of `max(1, len/3)`; candidates are scanned in the order given and ties keep the earliest, so deterministic candidate order gives deterministic suggestions. Used by scene typos and `L3002`.

**collections** — `StableMap`/`StableSet` wrap `BTreeMap`/`BTreeSet`, iterate in sorted key order (deterministic by construction), serialize transparently, ECS component storage is dense ascending `keys`/`values` columns plus a slot table (`ludion-ecs` `storage.rs`), not a `StableMap`. **Sorted key order is a contract, not an implementation detail:** the ECS query join is a sorted merge that would silently drop rows on an insertion-ordered column, so only another sorted-iteration map may ever back these types.

**rng** — `new(seed)` uses PCG's canonical default stream; `new_with_stream(seed, stream)` follows the standard seeding procedure. `next_u64` is two u32 draws, high word first; `gen_range_*` use rejection sampling (no modulo bias). State is serde, so snapshots and replay keyframes carry it.

**par** — chunk-level data parallelism whose results are a pure function of the input and the chunk size. `par_chunks(items, chunk_size, f)` hands each chunk an exclusive `&mut` sub-slice (disjoint writes); `par_map_chunks` returns per-chunk values in ascending chunk order whatever order they completed in; `ordered_reduce` folds those in the same order (float addition is not associative, so completion-order accumulation would make a sum depend on machine load). Panics are deterministic: every chunk runs and is joined, then the lowest-index panic propagates. Worker count is a process-global default (`set_threads`; unset, resolved on first use from `LUDION_THREADS` or the machine's capped available parallelism) with a thread-local scoped override (`with_threads`), so concurrent caller threads hold independent counts; effective parallelism is `min(count, chunk count)` and an effective `1` runs inline with no spawns. Chunk size is part of the determinism contract; thread count never is. See determinism for the rules and `Plan/deterministic-job-system.md` for the plan of record.

**math** — glam re-exported as-is (plain arithmetic is deterministic; Rust does not auto-contract FMA). Every transcendental routes through pure-Rust `libm` because platform C libm differs between Windows and macOS. On the sim path always call `ludion_core::math::sin(x)`, never `x.sin()` — clippy rejects the inherent method. glam itself runs on its `libm` feature (workspace `Cargo.toml`), so `Quat::from_rotation_y`, `slerp` and `Vec2::from_angle` are cross-arch deterministic too. The sim-grade rotation and transform composition (`euler_xyz_degrees_to_quat`, `Trs`, `Affine3`) is scalar `f32` in a fixed order instead: the order is written out here, so this crate's bit fixture pins it rather than whichever glam backend (SSE2, NEON, scalar) a target compiles; the fixture must reproduce unblessed on both pinned machines.

**time** — sim time is an exact integer tick count, never an accumulated float `dt`. `TickRate::DEFAULT` is 60 Hz; `TickRate::hz_of(hz)` panics on zero. `SimTime::seconds()` is derived on demand and never fed back into state, so no drift accumulates.

## Verify

```
cargo test -p ludion-core                     # unit tests + doctests
cargo clippy -p ludion-core -- -D warnings    # denylist enforcement
cargo run -p ludion-cli -- explain L0001      # table lookup end-to-end
```

## Gotchas

- `DiagnosticCode::as_str` falls back to `"L????"` on invalid bytes (`diagnostics.rs`), never an error — build codes only through the validated constructors, or a bad code prints as `L????` and `ludion explain` cannot find it.
- Swapping `next_u64` (two `next_u32` draws) for a native 64-bit draw would silently change every seeded sequence and invalidate world hashes.
- `sqrt` is the one transcendental clippy does not ban (IEEE sqrt is correctly rounded everywhere, and `Vec3::length` uses it), so callers may write `x.sqrt()`. `math::sqrt` still goes through libm — the optional auditable route; don't "optimize" it back to `std`.
- `SimTime` equality is by `(ticks, rate)`: the same seconds at different rates are unequal.
- `par::set_threads` is process-global, so a test that moves it perturbs any concurrently running test that has not scoped its own count with `par::with_threads`. Scope it; reach for the global only from a host deciding a whole process's budget.
- A `par_chunks` closure that writes outside the slice it was handed compiles fine and is exactly the bug the module exists to prevent — the borrow checker only guards the slice boundaries, not what else the closure captures.
- `StableMap` omits `retain` and ranges on purpose; add methods to the newtype rather than exposing the inner map mutably.
