# Renderer probes

**Scope:** How a `ReflectionProbe` becomes pixels: the six-face capture, the ranked cluster-mask shading in `reflections`, the content-addressed store and its hosts, and the dump and observability surfaces. The authoring side (the field table, placing, the bake commands) is `ludion docs reflection-probes`; the blend site is `ludion devdocs renderer-reflections`; the trace blended over probes is `ludion devdocs renderer-ssr`; the design of record is `Plan/reflections.md`.

## Layout
- `crates/ludion-renderer/src/probe_capture.rs`, `shaders/probe_face.wgsl` — the probe capture (below).
- `crates/ludion-renderer/src/probe_shade.rs`, `shaders/snippets/{probes,cluster_grid}.wgsl` — the ranked probe list and cell masks, the binding-free probe maths (`probe.rs` holds the CPU twins), and the cluster cell lookup shared with `lights.wgsl`.

## Dataflow
### Probe capture
`probe_capture.rs` captures each `RenderScene.probes` entry once, at the top of `prepare_frame`: six faces of `QualityParams::ibl_specular_size` (no new quality field), prefiltered by `Ibl::prefilter_probe` into slot `i` of a renderer-owned cube array (`ProbeCubes`: texture, cube-array view, probe → slot table, face size, `max_lod`). The in-memory cache key is the face size plus each probe's entity and store key, so anything the store key hashes recaptures and a live frame only compares; a scene without probes frees the array and does no GPU work.
- **Probe world**: `RenderScene.probe_world` is a frozen `ProbeWorld` (an `Arc<RenderScene>` and a process-unique id) that every capture reads in place of the live frame; the probe list and positions stay live. The engine freezes it from the frame-0 extract before the first tick or render after a load-class event (`commit_world`, an `asset.reload` of a cached asset or data doc, `set_textures`), so a bake and a host that ticks first capture the same world and hit the same keys. Without one (renderer-only callers) the capture reads the scene itself. `Probes::world_key` memoizes the world key on (probe world id, quality, params, code key, face). A re-freeze after a mid-session reload or a restore captures the world as it stands, not frame 0.
- **Derived scene**: each face is an ordinary frame (`prepare_frame` + `build_probe_capture_graph` + `Gpu::execute_into`) of a clone of the scene with the sprites, particles, text, ground markers, UI, debug lines, probes and `debug_view` emptied, `ssao`/`ssr`/`shafts`/`dof` zeroed, and the sun disc off (the IBL excludes it, so a probe does) and the sun's `cascades` cleared (a face uses the anchored box). Textures, mesh assets, lights, sun, GI and voxel stay, so every cache is a hit. Passes: shadow, gi_inject, scene, reflections, transparents, then `probe_face`.
- **Faces and the flip**: wgpu layer order +X, −X, +Y, −Y, +Z, −Z; up = +Y, +Y, −Z, +Z, +Y, +Y; world-axis-aligned (a probe's rotation belongs to its box proxy). The cube convention is left-handed against `look_to_rh`, so a face renders unmirrored and `probe_face.wgsl` flips x at store. Never flip the projection: it reverses the winding and fights `is_mirrored`. `capture_faces_match_the_cube_convention` pins it.
- **Geometry only, alpha is sky visibility**: `probe_face` writes `hdr_safe(scene.rgb)` on geometry and rgb 0 with alpha 1 where `scene_depth >= 1.0` (`scene`'s own alpha is 1 for both), so a prefiltered texel is geometry radiance plus the sky fraction. The sky itself comes from the live sky cube at shading time, which also means `--dump-probes` faces show black sky.

### Probe shading
`build_probe_list` ranks the extract indices by `probe_rank`; GPU probe `k` is rank `k`, and bit `k` of a cluster cell's `u32` mask (`probe_masks`, bounding spheres through the lights' margins) says the probe may reach it. The pass walks a cell's set bits lowest first, takes at most four with `weight > 0`, each `weight × (1 − coverage)`, and `fill = Σ probe · dfg_specular(ab, F0) · spec.a + sky_fill · (1 − coverage)`; SSR then mixes over `fill`. Occlusion: the probe term takes specular occlusion only, sky visibility stays on the sky fill. Box lookups intersect the oriented box, spheres the sphere (`probe_lookup`). The ray fed to `probe_lookup` is the lobe's dominant direction `rd`, not the mirror ray (`renderer-reflections`). The weight is 1 inside the volume and falls linearly to 0 over `blend` outside it (Euclidean distance); a point in that shell is clamped onto the volume before the lookup, and `probe_masks` grows each bounding radius by `blend`.
- **Relight** (`Plan/reflections.md` decision 17): a probe's radiance is `probe_relit` = `T · ratio + E · (1 − ratio) + a · sky · k` (clamped at 0 before the sky term; at ratio 1 the E term is exactly 0), `T` the prefiltered capture and `E` its emissive part, `sky` the live sky cube sampled along the fitted dominant direction (decision 31) at the sky fill's own LOD and `k` = `ibl_intensity` (0 with no `Environment`). `ratio` = `probe_axis_ratio` = `probe_ratio(baked E, live E)` per channel, 1 where baked E ≤ 1e-6, with E weighted by the ambient-cube weights `n · n` over the rows `probe_axis_rows(n)` picks, `n = −normalize(dir)` the facing of the surface the lookup hit (`dir` from `probe_lookup`). E is the normal-free diffuse irradiance at the capture point, one value per cube axis (+X −X +Y −Y +Z −Z), from `probe_relight.wgsl` (`probe_relight.rs`, in the capture code key): baked on face 0 of each capture (`Renderer::capture_probe_face(measure)`, `ProbeCubes.irradiance`, `ShadeProbe.baked`, six `vec4`) and dispatched per frame by the `probe_relight` graph compute pass into the `probe_live` transient (`MAX_PROBES`×6 rgba32float, one row per axis, binding 12, timed like any pass). The dynamic GI injection is not in E. `E` is the capture's fourth target: the scene pass's `fs_capture` entry (`mesh.wgsl`, `CaptureOut` location 3) writes `mix(emissive, flash.rgb, flash.a)`, `probe_face.wgsl` mirrors and sky-masks it like the lit face, and `Probes::resolve` prefilters it into a second slot-matched cube array (`ProbeCubes.emissive`, binding 13 of `reflections`), allocated by the first probe whose emissive mip 0 is nonzero and only then; `ShadeProbe.params.z` = 1 marks a probe that samples it (`ProbeCubes.emissive_slots`). A flagged scene costs one more cube per slot (about 4 MB per probe at FULL, 1 MB at LOW). Only the opaque mesh pass writes `E`: a transparent emissive lands in `T` and still fades with the ratio, and an opaque emissive seen through a transparent keeps its full `E` while its `T` is attenuated. CPU twins: `probe::{axis_rows, axis_ratio, ratio, relit}`.
- **Transparents**: `probes.wgsl` is binding-free so a transparent mesh composes it; none exists. Its fragment would bind 14 mesh textures (the BRDF LUT among them) + sky cube + probe array = 16, the floor, plus the probe mask buffer, `probe_live` and the sky cube for `probe_relit`.
- A frame with no probe uploads count 0, binds a 1×1 fallback array and is byte-identical to a probe-less renderer.

### Probe store
`Renderer::set_probe_store(Some(dir))` (default `None`: capture fresh) makes resolve load `<dir>/<key:016x>.ktx2` per probe, or capture, read the slot back and write the entry. Hit, miss and store-less slots are byte-identical (`probe_store.rs`).
- **Key** = `probe_key(world_key(face_scene(scene, ZERO, 0), …), position)`. It is built from the *face scene*, so a sprite, the sun disc, `ssr` or the camera never moves it. `world_key` destructures `RenderScene` with no `..`: a new field is a compile error until it is hashed or its exclusion argued. Small `Copy` structs hash through `Debug` (every field, automatically); meshes by `MeshData::hash` plus each map's `identity()`, wrap and scales; the voxel grid by `hash`. `post` is excluded (the capture graph has no composite, and the face scene zeroes the strengths that gate the screen-space chains). Machine terms: the `Quality` toggles, `QualityParams`, face size, the shader code key (`Renderer::capture_code_key`: every registry shader as composed, plus `ibl`, `gi_bake`, `gi_inject` and `probe_relight`; a reload clears it) and `PROBE_BAKE_VERSION` (bump when capture or prefilter bytes change for the same input; `probe_bake_pin_tests` captures `tests/fixtures/probe-bake-pin.yaml` on the pinned adapter and fails when the numeric signature in `probe-bake-pin.json` moves with the version unchanged (one term dominates each face of the fixture so a 2% change in it clears the tolerance; the emissive layer's prefilter and the GI dynamic injection are not seen), then `LUDION_BLESS=1 cargo test -p ludion-engine --lib probe_bake_pin` re-blesses it, refused without a bump). The store is per machine; across machines the tier is perceptual. The adapter is deliberately not a term: `ludion export` bakes on the dev machine's GPU and ships the entries, which the device looks up by key, so an adapter term would make every shipped entry miss (`--probes rebake` is the escape).
- **Position only.** The capture is world-axis-aligned, so shape, blend, priority and rotation shade but never rebake.
- **Entry**: KTX2, `R16G16B16A16_SFLOAT`, six faces, mips smallest first, each mip's faces back to back (a probe that sees emissive is a two-layer array, each mip holding the lit layer's faces then the emissive layer's; `layer_count` 0 otherwise), plus the baked irradiance as a `LudionProbeIrradiance` key/value entry (`ludion_assets::cooked::{write,read}_probe_cube`). A missing or invalid entry, or one without the irradiance, is a miss and is rewritten. Writes go to `<name>.<pid>.tmp` then `rename`; a failed write is dropped.
- **Eviction** is by last use. An entry's mtime is its last-used stamp: a write sets it, a store hit refreshes it (`probe_store::stamp_used`, a short-lived thread, because a hit lands on the sim thread inside a frame, which reads no clock and waits on no I/O; best-effort, a read-only store only loses a stamp). `ludion sync`'s warm is the only pruner (`prune_store`, via `ludion_engine::prune_probe_store`): an entry unused for 14 days goes, then the oldest past the 4 GiB cap, never one used within 24 h and never a key the warm itself resolved (`keep`). The warm knows only a subset of the valid keys (other qualities, scenes the CLI skips, scenes outside the default scene's directory), so pruning by key would delete live entries. A cap still exceeded is reported (`probe_store_over_cap`) and not an error. A `<key>.<pid>.tmp` older than an hour is dead-writer debris; a live writer's is fresh. Only the project's own store is walked.
- **Hosts.** `Engine::set_probes(ProbeSource)` is the render-only axis (never hashed or recorded). `run`, embed and `serve` host `Store` (the dir is `<project>/.ludion/cooked/probes`, the project being the `ludion.toml` ancestor, else the project root) unless `--probes rebake`, which `dev` forwards to every child. `render`, `test`, goldens, `--profile` and `ludion profile` stay `Fresh`. A `Store` miss is an `L1279` warning. `Engine::bake_probes(force)` is the bake core: it forces cooked textures and the store, because a cooked map's identity is its cook key, so a `--textures source` host misses a bake's entries.
- **Dump.** `ludion render --scene S --dump-probes DIR` (`Renderer::read_probes`, `probe_dump.rs`) writes `probe-<rank>-captured.png` (the six raw faces) and `probe-<rank>-prefiltered.png` (a row per mip) as unexposed sRGB bytes, plus `probes.json` (with a per-probe `capture_ms`).
- **Observability.** `FramePhase::ProbeBake` brackets each captured probe (loaded ones are not), feeding `LoadProfile.probe_bake_ms`; `ProfileReport.probes` is hits against captures; the `probes` debug-draw category (`extract::probe_debug_lines`) and `render.debug` `view: "probe_index"` are the live views.
- It captures fresh and never touches the store; `stored` only says a `Store` host at this quality would find the entry. Keys come from the same `store_keys` as `resolve`, taken from a cooked-texture host's extract (`key_source: "store-host"`; `"dump"` under `--set`), so they match a bake's.

### Debug view
- **`probe_index`**: `probe_debug` (`probe_debug.wgsl`) replaces `composite` the same way via `PostChain.probe_view`, set only when the scene has probes (else the normal frame is drawn and the summary says so). Same mask walk as `reflections`; the winner is the largest `weight × (1 − coverage)`.
  Colour = the no-probe gray 64 mixed toward `PROBE_VIEW_PALETTE[rank % 8]` (sRGB) by that contribution, so a barely-weighted probe reads near gray; black only where there is no surface.

## Rules
- Probe shape, blend, priority and rotation shade but never rebake: the capture is world-axis-aligned and keyed on position (`Probe store`).
