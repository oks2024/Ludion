# Ludion

An LLM-first 3D game engine in Rust. The agent (you) is the primary developer and primary user; humans (level designers, game designers) are first-class users of the same core, through a visual editor that is a peer client — never a privileged one. The name is a Cartesian diver: apply a command over the protocol, observe a deterministic, verifiable response.

**Read `engine-pillars.md` before making design decisions** (the why) **and `engine-architecture.md` before writing code** (crate graph, boundary rules, threading model, protocol spec, build order). This file is the operational summary; each plan's Status section in `Plan/` is the record of what shipped, and `Plan/owed.md` is the ledger of everything waiting on a human, the second pinned machine, or a trigger. Subtree rules load on demand when you read a file there: `games/<game>/CLAUDE.md` (vigil's hashed-state and replay traps), `editor/CLAUDE.md` (the parity gate in practice, the live-smoke rule) — a rule only one subtree needs goes in its file, not here.

## North Star

Every decision is scored against one metric: **how many autonomous iterations can an agent perform — change, verify, correct — before a human needs to look at the screen?** When agent ergonomics and human ergonomics conflict, agent ergonomics win.

## Non-negotiables (from the pillars)

- **One command core, many clients** (Pillar 2). Every capability is a typed, serializable command on one canonical layer; the engine hosts a native wire protocol, and CLI, MCP adapter, and editor are thin peer clients. **Hard parity gate:** nothing ships in the editor unless it already exists as a protocol command. No editor-private endpoints. **Pipeline verbs satisfy the gate as CLI commands** (`import`, `generate-map`, `generate-atlas`, `gen` — batch producers of committed files, not live world manipulation): the editor's host invokes them as a subprocess with `--json` (`Plan/comfy-generation.md` decision 15).
- **Text is the single source of truth** (Pillar 4). Scenes, materials, palettes, tilemaps: structured text with canonical serialization — stable field order, stable entity ordering, floats as ryu shortest-round-trip (**never fixed precision — that is a data-loss bug**; quantize at the source, e.g. a gizmo, never in the writer). Any client's edit produces a minimal git diff.
- **Tiered determinism** (Pillar 3). CPU-side is bit-exact: fixed timestep, seeded RNG, reproducible sim. Images gate on perceptual comparison (SSIM + tolerance) with structured diff reports; bit-exact goldens only on pinned GPUs. Test mode disables temporal accumulation. Flaky tests are P0 bugs.
- **Rust is the only Turing-complete layer.** No embedded scripting language. Designers describe behavior; the agent writes hot-reloadable Rust. Tunables live in declarative text.
- **Errors are the UX budget** (Pillar 5). Target rustc's bar: what's wrong, where, why, likely fix. Validation errors are readable messages with suggestions, not crashes; protocol errors are structured and actionable.
- **Regularity over cleverness** (Pillar 6). One obvious way per task. No macro-heavy DSLs, no deep generic builder chains. Encode invariants in the type system (typestate) so violations are compile-time messages.

## Settled architecture

Full detail in `engine-architecture.md`; headlines:

- **Language:** Rust all the way down. **Graphics:** wgpu, introspectable frame graph (`--dump-graph`, `--dump-timings` as JSON). The renderer always targets an offscreen texture; presentation is frame streaming, in-process present (`Engine::attach_surface`) the one host seam. wgpu is held loosely: the frame graph's declarative interface is the migration seam, no preemptive backend-abstraction traits (architecture doc §1, §2).
- **Platforms:** Windows + macOS, both first-class (two pinned GPU targets for bit-exact goldens, CI matrix and Tauri builds on both). Nothing platform-shaped in `crates/` or `games/` (no `cfg(target_os)`); ports land as PC work behind cargo features.
- **Content style:** HD-2D / stylized (sprites, billboards, low-poly on a full 3D pipeline) at native ≥1080p with a modern post stack — a default that keeps scope finite, **not an engine restriction**; the renderer grows toward full PBR under real content demand (`Plan/roadmap-voxel-mesh-pbr.md`).
- **Structure:** workspace of small, orthogonal `ludion-*` crates — the relevant API surface must fit in an agent's context and `cargo check` must stay fast enough for a 20-iteration fix loop. Games depend on the `ludion` facade (`use ludion::prelude::*`); `ludion::run` (argv shell) and `ludion::launch` (argv-free, `LaunchRoots`) host one shared engine; the `wire`/`window` features make the server and window optional.
- **Scene/data model:** custom ECS (freeze-listed, milestone-minimal) + strict-subset YAML 1.2 scenes with a canonical writer; JSON on the wire; TOML for the project manifest. JSON Schema generated from the component registry validates file and wire payloads.
- **Editor:** Tauri + React, out-of-process protocol client; TS protocol types generated from JSON Schema in CI. The human viewport and the agent screenshot query are the same frame-streaming endpoint.
- **Scripting/hot reload:** game crates are bins; `ludion dev` does recompile + restart-with-state-snapshot (`engine.snapshot`/`engine.restore`). No dylib reload.
- **CLI** (bin `ludion`; detail in `--help` and `ludion devdocs ludion-cli`): `new`, `check-scene`, `render`, `test`, `profile`, `dump-graph`, `explain`, `replay`, `sim-hash`, `trace`, `serve` (a scene over the wire), `dev`, `docs`/`devdocs`, `image-stats`; pipeline verbs `import` (glTF → canonical text; PNG → `kind: sprite`), `generate-map`/`map-check`, `generate-atlas`, `gen` (ComfyUI recipes), `bake-probes`, `sync` (`[[import]]` tables → ignored derived trees); write-side `voxel`, `sculpt`, `mesh pick`/`apply`; `export` (Xcode project for `ios`/`ios-sim`, `--run`).

## Source control

**Lore** — Epic's open-source VCS (Rust, pre-1.0) — is the **single source of truth**: repo `ludion`, branch `main`, on a private server (machine facts in the private `CLAUDE.local.md`, never here). Client and server are pinned to the same version (v0.8.6) and only ever upgrade **together**.

- **Commit with `node scripts/commit.mjs "<message>" <paths...>` — the one commit verb.** It syncs when the remote has moved, runs Lore-first (stage → commit → push; `--no-push` defers), then writes a snapshot commit onto the git mirror. Manual `lore commit`s are legitimate (a `--all` run emits a catch-up mirror snapshot); manual **git** commits are not. **Paths are required**: a path-less sweep commits whatever else is dirty — another instance's half-finished work, anything an ignore rule missed (both have happened); `--all` asks for the whole tree deliberately; a >500-file staged set aborts unless `--force`. A failed push exits non-zero: **never stack a second commit on an unpushed one**, or one divergence becomes two.
- **A diverged branch is repaired by hand — load the `lore-merge` skill before running any lore verb on it.** The wrapper refuses to help, and three verbs that look right destroy work: `lore stage merge`, `resolve mine`/`theirs`, and above all **`lore unstage` mid-merge, which silently overwrites the other machine's edits later**. `lore sync` leaves `<<<<<<< ours` markers and `<path>~base`/`~mine`/`~theirs` sidecars — delete the sidecars, never commit them. Merge when no subagent is mid-edit.
- **Git is a derived, write-only mirror and the repository's public face**: every commit message and every file outside the private paths is published, so write both for a stranger. Never author git by hand (no `git commit`, no branches); the wrapper pushes mirror branch `main` to GitHub remote `origin`. Its history starts at a fresh root (earlier history lives only in Lore); `lore history` and `lore status --scan` stay authoritative.
- **The ignore delta is the privacy boundary.** Lore reads only the root `.loreignore`; git reads `.gitignore`. Paths in `.gitignore` but not `.loreignore` are private to Lore and never reach the mirror (`.exarch/`, `infra/`, `ci/teamcity/`, `CLAUDE.local.md`, and `Plan-Private/` — every private plan lives there); every other ignore rule appears in both, mirrored by hand. The privacy canary (`scripts/privacy-canary.mjs`, in `check.mjs` and `commit.mjs`) is the backstop, not the rule — **never write an address, hostname or personal path outside a private path.**
- Lore stores exact bytes (no line-ending translation), so the LF-everywhere tree and binary goldens (`.png`, `.lrp`) sync byte-identical. No rebase/stash/blame/tags: history is linear commits on `main`.

## Working conventions

- **One-command verify loop:** `node scripts/check.mjs` runs every local CI gate in parallel and prints a pass/fail summary plus the errors (per-step logs in `.build/`). `--scope <paths>` runs the gates your paths reach — a Coder's loop and a subtask commit's gate; the whole suite gates a milestone (a wave or feature close, a hand-back to the user), the tech lead's job. `--fix` re-mirrors, regenerates and formats; `--full` adds the release-grade gates; other flags in `--help`. **Budget: ~4.5 minutes for the default suite on the reference 32-core Windows box**, under cargo-nextest (`cargo install cargo-nextest --locked` once per machine). A breach means re-measure (the summary names the slow tests) — never delete or weaken a gate. The canonical gate set is `.github/workflows/ci.yml` (on demand only; no per-push lane) + `ci/scripts/`; a gate added in one is added in the other — except a Lore-only game's lanes (vigil's) and the public-tree lane, which run in `check.mjs` and TeamCity only.
- **A test failure that moves between runs may be the box, not the suite** — `os error 1224` on a PNG write means a viewer or indexer holds the file mapped (close it, delete `target/tmp`). `ludion devdocs test-box-failures` before diagnosing a flake.
- Vertical slice before general systems. Do not gold-plate subsystems the current milestone doesn't exercise.
- Every public API ships with a small, complete, runnable example — examples are the primary documentation format for agents.
- **Consult agent-docs before changing a subsystem.** `ludion docs <topic>` serves `docs/` (building a game; embedded in the binary), `ludion devdocs <topic>` serves `dev-docs/` (editing `crates/`; checkout-only); bare, each lists its topics. Crate docs bind that crate; cross-cutting topics (`determinism`, `crate-graph`, `profiling`) bind every crate they name — read `profiling` before touching any timing site. **Pull on demand:** fetch only the topic you're about to work in; skip docs for trivial edits. **`crates/ludion-cli/embedded-docs/` is a checked mirror of `docs/`** — editing a `docs/` topic fails `cargo build -p ludion-cli` until `check.mjs --fix` re-mirrors it. Writing topics and their size budgets is the `ludion-docs` skill's job.
- Headless operation is the default; windowed is the special case.
- Before adding a second way to do something, remove the first.
- **Comments earn their place.** Prefer self-explanatory code; comment only what the code can't say — the *why*, a non-obvious invariant or constraint. Short; no restating the code. A verbose or stale comment is a defect. **A comment describes state, never schedule** — no "this wave", "lands in Wave 3", "a later phase"; sequencing belongs in `Plan/`.
- **`dispatch.rs` contains no logic, only routing.** Every `Command` variant gets a ≤10-line match arm delegating to a plain function in the owning domain crate. The exhaustive match IS the parity gate: a command without a handler is a compile error.
- **Crate boundary rules** (each prevents a specific cycle — architecture doc §2): `ludion-protocol` never names a concrete component type (wire payloads are `serde_json::Value` + registry name); `ludion-ecs` never knows YAML exists; `ludion-assets` never sees a wgpu type; `ludion-engine` never depends on `ludion-server`.
- **Determinism rules for all sim-side crates** (enforced by per-crate clippy denylists; `ludion devdocs determinism`): no std `HashMap`/`HashSet` (use `ludion_core::collections`); no wall clock in sim (time arrives as `SimTime`/`FrameIndex`); one seeded `DeterministicRng` resource, never `thread_rng`; transcendentals via `ludion_core::math` (pure-Rust libm); systems sequential in explicit registration order, no rayon, no ad-hoc threads — sim parallelism only via `ludion_core::par` (thread-count-invariant results, on by default; `ludion devdocs sim-parallelism`); deterministic entity free-list order. The thread count is a per-*machine* property — `LUDION_THREADS` in the environment or a host's `--threads`, never a committed file — and every profile report carries `sim.threads`: never compare two measurements across counts.
- **Never introduce `Arc<Mutex<World>>`.** The sim thread solely owns `World`; all reads and writes — queries and pause/step included — flow through the one command queue and apply at frame boundaries.
- Every diagnostic carries an `L####` code registered in `ludion-core`'s code table (`ludion explain L####` must work), with JSON Pointer paths into documents where applicable. Sim-side reporting goes through `report_diagnostic` into the `Diagnostics` resource — never `eprintln!`.
- **Generated content is write-only for agents.** A scene bearing `generated_from:`, a committed atlas pair and a derived mesh tree are never hand-edited — iterate edit-source → `generate-map`/`generate-atlas`/`mesh apply` → check; the drift gates enforce byte-identity.
- **Committed `.lrp` replays are recorded at the default extent** — mouse coordinates are render-target pixels, so a resized session is a different input trace, and pre-extent engines ignore the header field. A hash-moving change re-records the corpus last, after the schema snapshot.
- **Implementation plans live in `Plan/`** — one markdown file per plan, its Status section the shipping log. Plans for deferred work record the evaluation, phasing, and trigger so the decision is made from a written analysis, not under pressure.
