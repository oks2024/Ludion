# Content and effect components

**Scope:** the fields and defaults of the components a scene draws or plays content through, split
out of `ludion docs components` (registry rules and drift safety live there). The wider topics — atlas
regions and flipbooks, the analytic particle model, bullet patterns, and positional audio — are named
against each row below.

| Component | Fields (default) |
|---|---|
| `Sprite` | `texture: Option<String>` (none → white quad), `atlas: Option<String>` + `frame: Option<String>` (a `kind: atlas` document and one of its regions — set together, and never beside `texture`: `L1151`), `size: Option<[f32;2]>` (none → the atlas region's pixel size ÷ its `pixels_per_unit`, else `[1,1]`), `color: [f32;4]` RGBA (`[1,1,1,1]`; RGB `>=0`, alpha `0..=1`: `L1263`), `billboard: bool` (`false`), `lit: bool` (`false` — unlit is texel × tint with no light lookup; `true` takes light like any surface), `layer: i16` (`0`) the primary sort key — sprites draw in `(layer, view depth back-to-front, scene order)`, a pure ordering, never a Z displacement — `blend` (`alpha`\|`additive`), `flip_x`/`flip_y: bool` (`false`, mirroring the UV rect), `uv_repeat: [f32;2]` (`[1,1]`; how many times the frame tiles across the quad — a non-default value wraps), `uv_scroll: [f32;2]` (`[0,0]`; UV units per second, evaluated from sim time at extract — wraps), `flash: f32` (`0.0`, in `0..=1`) lerping the final colour toward `flash_color: [f32;3]` (white, HDR-capable, `>=0`: `L1263`). Drawn size is exactly `size`, further multiplied by the `Transform.scale` x/y. **A non-billboard sprite is an XY quad facing +Z.** Collision runs on the game's chosen `Plane` (`ludion docs collision`), not necessarily this quad's own plane; a sprite game keeps them aligned with `Engine::builder().plane(Plane::Xy)` (`ludion docs visuals --section "Which plane is 2D?"`). See `ludion docs sprites` |
| `Tilemap` | `cell_size: f32` (`1.0`), `legend: map<glyph, TileAppearance>` (empty), `rows: [String]` (empty) — a grid of single-glyph cells. A legend entry takes `Sprite`'s own field shapes: `texture` **or** `atlas` + `frame` (`L1151` for a half-written pair or both at once), plus `color` (`[1,1,1,1]`; RGB `>=0`, alpha `0..=1`: `L1263`), `lit`, `flip_x`, `flip_y` (all `false`); `layer: i16` (`0`) is one sort key for the whole grid; a cell's world size stays `cell_size`, never the region's. See `ludion docs tilemaps`, and `ludion docs sprite-sheets` for the atlas form |
| `MeshGrid` | `cell_size: f32` (`1.0`, `> 0`), `legend: map<glyph, Mesh>` (empty), `rows: [String]` (empty, a space is an empty cell), `orient: [String]` (omitted; `0`-`7` per cell) — a `Tilemap` of meshes in the entity's local XZ plane. `L1019`/`L1020`/`L1243`; legend colours are `L1263` like `Mesh`'s. See `ludion docs mesh-grids` |
| `ParticleEmitter` | `shape` (`point`) — `point`\|`sphere`\|`box`\|`disc`/`extent: [f32;3]` (`[0.5,0.5,0.5]`, `>=0`)/`rate: f32` (`40.0`, `>=0`)/`burst: u32` (`0`)/`started: FrameIndex` (`0`)/`duration: f32` (`0.0` = endless, `>=0`)/`life: [f32;2]` (`[0.8,1.4]`)/`speed: [f32;2]` (`[1.0,2.5]`)/`spread_deg: f32` (`30.0`, `[0,180]`)/`gravity: f32` (`0.0`)/`drag: f32` (`0.0`, `>=0`)/`floor: f32` (`-f32::MAX` = none)/`start_size: f32` (`0.25`, `>=0`)/`end_size: f32` (`0.0`, `>=0`)/`start_color`/`end_color: [f32;4]` (white / transparent white)/`blend` (`alpha`\|`additive`)/`softness: f32` (`0.5`, `[0,1]`)/`seed: u64` (`0`) — an analytic effect (never entities, a pool, or a GPU sim): the live set is a pure function of `(emitter, sim time)`, capped at `PARTICLE_MAX_LIVE_PER_EMITTER` = 4096 live particles (`rate · life[1] + burst`); a negative scalar (`rate`, `duration`, `drag`, sizes) is `L1014`; a negative or non-finite `extent`/`life`/`speed` element, an inverted `[min,max]` or an over-cap population is `L2107`; the colours take RGB `>=0` and alpha `>=0` (`L1263`; alpha is clamped to 1 at draw, so above 1 holds full opacity longer through the fade). See `ludion docs particles` |
| `Volley` | `source: Option<EntityId>` (none) who fired (saved as none once the shooter is gone)/`pattern: String` (`""`) + `bullet: String` (`""`) the `kind: pattern` doc and bullet-kind names/`started: FrameIndex` (`0`)/`shape` (`ring`\|`arc`\|`random`, `ring`)/`count: u32` (`0`, at most 256 — the kill bitset's width, `L2108`)/`angle_deg`/`spread_deg: f32` (`0`)/`speed: [f32;2]` (`[0,0]`)/`seed: u64` (`0`)/`killed: [u64;4]` (zero) — a per-bullet kill bitset the engine only reads. A fired volley's own entity: bullet *i*'s trajectory is a pure function of `(volley, bullet kind, i, now)`, never stored. See `ludion docs patterns` |
| `PatternPlayer` | `pattern: String` (`""`, empty = plays nothing)/`started: FrameIndex` (`0`)/`target: Option<EntityId>` (`None`) — which `kind: pattern` document an entity plays, from which frame, and who an `arc { center: aim }` volley aims at. See `ludion docs patterns` |
| `PathFollower` | `path: String` (`""`, empty = inert)/`speed: f32` (`1.0`, metres per gameplay second, may be negative)/`mode` (`loop`\|`ping_pong`\|`once`, `loop`)/`orient` (`none`\|`yaw`\|`frame`, `none`; faces −Z along travel)/`phase: f32` (`0.0`, metres along the path; rewritten every tick) — rides its entity's `Transform.translation` (and `rotation` when oriented) along a `kind: path` document, before game systems, on gameplay time. An unloadable path is `L1215`. See `ludion docs path` |
| `Animation` | `clip: String` (`""`), `started: FrameIndex` (`0`), `speed: f32` (`1.0`, `>=0`), `hold: u32` (`1`, `>=1`: `L1317`; omitted at `1`; ticks each pose is shown) — which clip this entity plays, and from which frame: an entry of a `Mesh.shape: assembly` model's or `character`'s `clips:` map, or, on a prefab instance's root part, of the prefab's `clips:` (`ludion docs prefab-animation`), or of a `Sprite`'s atlas `flipbooks:` (`ludion docs sprite-animation`). Playback is **visual-only** unless the game consumes `AnimationEvents` (clip timing is then sim input): the pose is derived at render time from `(clip, sim time)`, so the sim, the world hash and a replay are untouched otherwise. An unbound clip name renders the rest pose (the assembly's, or the `Sprite`'s authored `frame`). Game code writes it when the *choice* changes — re-stamping `started` every frame restarts the clip every frame. Crossfade: `from: String` (`""`), `from_started`, `fade_started: FrameIndex` (`0`), `from_speed: f32` (`1.0`), `fade: f32` seconds (`0.0`, `>=0`), all omitted from text at their defaults; `anchor`/`from_anchor` (`{started, frame, ticks, grid_ticks}`, omitted when absent; `grid_ticks` only under a `hold`, written between two steps) are written by `set_speed(&mut animation, speed, ctx.game_time)`/`crossfade`, which change speed mid-clip without a jump; call `crossfade(&mut animation, clip, seconds, ctx.game_frame)` instead of writing `clip`. While `fade_started + fade` has not passed, a character or assembly blends the outgoing clip into the new one (rotation slerps, translation and scale lerp; an empty or unbound `from`/`clip` is the rest pose), then is exactly the plain new clip. A sprite flipbook always hard-cuts: `fade` on one is `L1209`. Events: a game registering `animation_events` gets a per-tick `AnimationEvents` resource (`iter()`, `fired(entity, clip, name)`) of every authored/overlay event the clip clock crossed, plus `end` when a one-shot finishes (`end` is reserved: `L1198`); only the incoming clip of a crossfade emits |
| `AudioEmitter` | `sound: String` (`""`), `gain: f32` (`1.0`, `>=0`), `range: f32` (`10.0`, `>0`: `L1136`), `category` (`ambient`) — a loop placed in the world, positioned by its `Transform`. Synced on change (a new sound, bus or a gain move past 1%) at `gain · clamp(1 − distance/range, 0, 1)`, ground-plane distance from the camera, and stopped when inaudible; no system needed. See `ludion docs audio` |
